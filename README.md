## v2 — 트레이드오프 붕괴 탐지 (Trade-off Collapse Detection)

한국 상장사 「질적 전환」 탐지 퀀트 시스템. 명세서 v2 (2026-08-07) 구현체.

> **찾는 것은 "좋은 기업"이 아니라 "제약이 풀린 기업"이다.**
> 물량을 늘리면 단가를 깎아야 하고, 설비를 늘리면 ROIC가 떨어지고, 사람을 늘리면 인당
> 생산성이 희석된다. **질적 전환이란 이 대가를 더 이상 치르지 않게 된 상태다.**
> 그래서 점수화 단위는 개별 지표가 아니라 트레이드오프 쌍(TP)이며, 반드시 **곱**이다:
> `TP = z(개선의 크기) × z(치르지 않은 대가의 크기)`

> **"강제 재고(신용융자잔고)가 소진되었는가"** 이며, 그 판정이 단순 낙폭과대를 이기는지는

| 국면 | 조건 | 행동 |
|---|---|---|
| A 물타기 | 낙폭 크고 신용잔고율 높고 개인이 아직 순매수 | 진입 금지 |
| B 반대매매 진행 | 잔고 급감 + 개인 이탈 + 낙폭 가속 | 진입 금지 (칼날 낙하) |
| **C 소진** | 잔고율 자기이력 하위 + 개인 이탈 누적 + 기관 유입 + 변동성 진정 | **진입** |

### KRX 차단 대응 — 비KRX 데이터 스파인

KRX(마켓플레이스·pykrx·KIND)가 계정/IP 단위로 차단될 수 있다. `KRX_MODE = "OFF" | "AUTO" | "ON"`
로 제어하며, 차단 상태에서도 아래 경로로 **PIT 유니버스와 생존자편향 제거가 성립한다**.

| 필요한 것 | KRX 경로 | 비KRX 대체 경로 |
|---|---|---|
| 종목 발굴 | KRX 스냅샷 | FDR GitHub 캐시 + **DART corpCode**(폐지사 포함) + 네이버 시세목록 합집합 |
| 상장/폐지일 | KRX 명부 | FDR 폐지목록 + **가격이력 재구성**(거래가 있었다는 사실 자체가 상장의 증거) |
| 상장주식수(시총 분모) | KRX 시총 스냅샷 | **DART 주식총수현황** — 접수일 기준이라 PIT 가 더 엄밀 → 없으면 거래대금 대리 |
| 투자자 수급 | pykrx | **네이버 종목별 매매동향 JSON → HTML**(개인 없으면 `-(기관+외국인)` 근사, 등급 표기) |
| 신용융자잔고 | KRX 독점 | 수동 CSV 흡수 → 프록시(Fallback B). **강등되면 리포트 첫 줄에 등급이 찍힌다** |

생존자편향은 "제거했다"고 주장하지 않고 **잔존분을 측정해 표로 낸다**:
구간 내 폐지 종목 중 폐지 시점(±60일) 가격을 확보하지 못한 비율이 곧 남은 편향이다.

## 2. 구글드라이브 캐시 — 절대 1원칙

**기존 캐시·인덱스를 훼손하지 않는다.** 약속이 아니라 **구조**로 보장한다:

1. 인덱스의 진실은 **append-only JSONL 저널**이다. 기존 줄을 다시 쓰지 않으므로 코드가
   어떻게 잘못돼도 과거 기록이 사라질 수 없다.
2. `index.parquet` 은 저널의 파생물(캐시)일 뿐이며, 재생성 전 **항상 타임스탬프 백업**.
   백업에 실패하면 컴팩션 자체를 건너뛴다(저널이 원천이므로 유실 없음).
3. 컬럼은 **합집합으로만 확장**. 스키마가 달라도 기존 컬럼을 떨어뜨리지 않는다.
4. blob 은 **내용해시 경로**에 쓰므로 같은 내용은 재기록조차 하지 않고, 다르면 새 리비전.
5. 이미 드라이브에 있던 리포트는 **이동·개명 없이 경로만 등록**한다 (adopt-by-reference).
6. **삭제 API 자체가 없다.** 손상 파일조차 지우지 않고 `.corrupt` 로 격리만 한다.

```
{GDRIVE_ROOT}/
├── _shared/          ← 공용 인덱스: 다른 전략도 그대로 재사용
│   ├── index/{index.jsonl(원천), index.parquet(파생), _backup/}
│   ├── blob/research/report_pdf/<해시앞2>/<해시>.pdf
│   └── table/{krx_ohlcv_daily, dart_fnltt_raw, research_report_master,
│              analyst_master, report_analyst_link, nps_workplace_monthly, ...}
└── tcd_v2/           ← 전용 인덱스: 이 전략 고유
    └── table/{l1_features_*, l2_scores_*, backtest_returns_*}, reports/
```

공용 인덱스에 들어가는 것 = **원본과 범용 정제본**(가격, 재무, 보고서 원장, 애널리스트 원장).
전용 인덱스 = **이 전략의 해석물**(피처 패널, 스코어, 백테스트 결과).

## 3. 애널리스트 리포트 · 원장 연결

두 소스의 역할이 다르고, **합쳐야 원장이 완성된다**.

| | 한경컨센서스 | 네이버 금융 리서치 |
|---|---|---|
| 작성자(애널리스트) | ✅ 리스트 컬럼에 직접 | ❌ (PDF/상세에만) |
| 목표주가·투자의견 | ✅ `skinType=business` 9컬럼 레이아웃 | 상세페이지 `div.view_info_1 em.money` |
| 종목코드 | ❌ 제목의 `종목명(005930)` 에서 정규식 | ✅ `td[0] a.stock_item` href |
| 커버리지 | 배포 동의 증권사 한정 | 넓음 |

**함정과 대응**

- `skinType` 을 빠뜨리면 **6컬럼 레이아웃**이 와서 목표주가·작성자가 조용히 사라진다.
  → 컬럼 인덱스를 믿지 않고 **`<th>` 헤더 텍스트로 매핑**하고, 헤더가 없을 때만 내용 기반 폴백.
- 적정가격 `"0"` / `"-"` 는 "목표주가 없음"이다. `int("0")` 으로 넣으면 리비전 팩터가 오염된다.
- 네이버는 body 가 **EUC-KR 인데 meta 는 utf-8 이라고 거짓말**한다 → 예외 없이 글자가 깨진다.
  → 후보 인코딩별 **한글 가독성 점수**로 선택.
- 네이버 날짜는 `YY.MM.DD` → 1926년으로 파싱되는 사고를 후처리로 교정.
- PDF 다운로드가 HTML 로그인 페이지를 200 으로 반환할 수 있다 → `%PDF-` 매직바이트 검사.
- 증권사 사명 변경(미래에셋대우→미래에셋증권, 하나금융투자→하나증권, 이베스트→LS증권 …)을
  정규화하지 않으면 **같은 애널리스트가 소속 변경만으로 다른 사람이 되어** 목표주가 리비전이 망가진다.

**왜 애널리스트 식별이 전략에 구조적으로 필요한가**
D축 `d2`(상향 리비전)는 *같은 애널리스트가 같은 종목에 이전에 제시한 목표주가*와 비교해야 한다.
애널리스트 원장이 없으면 이 지표를 만들 수 없다. 장식이 아니다.

**무결성 감사**는 연도×소스별로 애널연결률·종목코드율·목표주가율을 표로 출력하고,
대형사 10+/중소형 10+ 커버리지 충족 여부를 판정한다.

> ⚠ 두 사이트 모두 `robots.txt` 가 `Disallow: /` 다. 사용자의 명시적 지시에 따라 수집하되
> 보수적 속도로 제한하고 그 사실을 로그에 명시한다. PDF 원문은 증권사 저작물이므로
> 로컬 캐시/분석 용도로만 사용할 것.

## 5. 강건성 · 킬 기준

`R1 누수민감도 → R2 TP vs 나이브⭐ → R3 퀄리티 직교화⭐ → R4 플라시보 → R10 정책반증 →
R5 절제 → R11 팩상관 → R6 PBO/DSR → R7 레짐 → R8 하위기간 → R9 회전율·용량`

- **R1** 은 두 부분이다. **R1a**(미래수익을 신호에 주입한 고의 오염본)가 판정 기준이고,
  R1b(실제 신호 1개월 선행)는 참고다. R1b만으로는 "하네스 둔감"과 "신호에 알파가 없음"을
  구분할 수 없기 때문이다.
- **R2** 가 이 시스템의 존재 이유를 검정한다. `z(개선)×z(대가회피)` 가 `z(개선)` 단독을
  못 이기면 트레이드오프 논리 전체가 불필요한 복잡도다. **유리하게 해석하지 않는다.**
- 킬 기준(⭐) 위반 시 `KillCriteria` 로 즉시 중단하고 그대로 보고한다.
  `STOP_ON_KILL_CRITERIA=False` 로 끄지 말 것.

## 6. 에러 국소화

모든 연산은 `PIPE.stage(...)` 안에서만 돈다. 실패하면 자동으로 출력되는 것:

- **실패 지점**: 스테이지 ID · 계층 · 경과시간
- **직전 입출력 스냅샷**: 무엇이 몇 행 들어오고 나갔는지, PIT 컬럼 유무까지
- **한글 진단 힌트**: 예외 패턴 → 원인·조치 (인증키 이중인코딩, 403 차단, 드라이브 미마운트,
  parquet 손상, 프로세스 병렬 실패, tz 혼재 …)
- **트레이스백 마지막 12줄**

실행 끝에는 스테이지 요약표 · **데이터 흐름 원장(I/O LEDGER)** · PIT 저장소 상태 ·
HTTP 수집 감사(소스별 성공률/차단) · 런타임 감사(C10) · 데이터 흐름 지도가 출력된다.

## 8. 알려진 한계 (숨기지 않는다)

1. **컨센서스 fwd EPS 시계열은 과거 복원이 불가능하다.** D축 `d1` 의 E 는 후행 12M 이익
   대리변수를 쓴다. 초기 구간일수록 오차가 크다. (§16.2)
2. **산업 분류는 현재 시점 분류**를 쓴다. 규모 버킷은 PIT 이지만 산업은 아니다.
   변경 빈도가 낮아 영향이 제한적이나, 완전한 C4 충족은 아니다.
3. **DART 콜드빌드는 일일 호출한도(20,000) 때문에 며칠 걸린다.** 진행률과 잔여량을 표시하고
   재실행 시 정확히 이어받는다. (§3 — 콜드빌드는 4시간 반복예산 밖)
4. **PACK-X 는 HS↔기업 매핑 테이블이 선행되어야 한다.** 5단계 파이프라인(수 주)은 자동
   구축 대상이 아니므로, 매핑이 없으면 팩이 자동 비활성화된다.
5. **하한선(§8.2)은 축 수에 민감하다.** 축 k개면 잔존율이 대략 `0.5^k`. 통합 파일보다
   팩별 단독 파일이 스펙의 "표본 붕괴 없이" 의도에 더 가깝다.
6. **이 전략은 우측 꼬리 의존적이다.** 상위 5% 종목 제외 시 성과가 사라지는지 매 실행
   측정해 출력한다. MDD 30% 초과 가능성이 높다.
