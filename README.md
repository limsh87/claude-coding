# TCD v2 — 트레이드오프 붕괴 탐지 (Trade-off Collapse Detection)

한국 상장사 「질적 전환」 탐지 퀀트 시스템. 명세서 v2 (2026-08-07) 구현체.

> **찾는 것은 "좋은 기업"이 아니라 "제약이 풀린 기업"이다.**
> 물량을 늘리면 단가를 깎아야 하고, 설비를 늘리면 ROIC가 떨어지고, 사람을 늘리면 인당
> 생산성이 희석된다. **질적 전환이란 이 대가를 더 이상 치르지 않게 된 상태다.**
> 그래서 점수화 단위는 개별 지표가 아니라 트레이드오프 쌍(TP)이며, 반드시 **곱**이다:
> `TP = z(개선의 크기) × z(치르지 않은 대가의 크기)`

## 2. 구글드라이브 캐시 — 절대 1원칙

**기존 캐시·인덱스를 훼손하지 않는다.** 약속이 아니라 **구조**로 보장한다:

1. 인덱스의 진실은 **append-only JSONL 저널**이다. 기존 줄을 다시 쓰지 않으므로 코드가
   어떻게 잘못돼도 과거 기록이 사라질 수 없다.
2. `index.parquet` 은 저널의 파생물(캐시)일 뿐이며, 재생성 전 **항상 타임스탬프 백업**.
   백업에 실패하면 컴팩션 자체를 건너뛴다(저널이 원천이므로 유실 없음).
3. 컬럼은 **합집합으로만 확장**. 스키마가 달라도 기존 컬럼을 떨어뜨리지 않는다.
4. blob 은 **내용해시 경로**에 쓰므로 같은 내용은 재기록조차 하지 않고, 다르면 새 리비전.
5. 이미 드라이브에 있던 리포트는 **이동·개명 없이 경로만 등록**한다 (adopt-by-reference).
6. **삭제 API 자체가 없다.** 손상 파일조차 지우지 않고 `.corrupt` 로 격리만 한다.

```
{GDRIVE_ROOT}/
├── _shared/          ← 공용 인덱스: 다른 전략도 그대로 재사용
│   ├── index/{index.jsonl(원천), index.parquet(파생), _backup/}
│   ├── blob/research/report_pdf/<해시앞2>/<해시>.pdf
│   └── table/{krx_ohlcv_daily, dart_fnltt_raw, research_report_master,
│              analyst_master, report_analyst_link, nps_workplace_monthly, ...}
└── tcd_v2/           ← 전용 인덱스: 이 전략 고유
    └── table/{l1_features_*, l2_scores_*, backtest_returns_*}, reports/
```

공용 인덱스에 들어가는 것 = **원본과 범용 정제본**(가격, 재무, 보고서 원장, 애널리스트 원장).
전용 인덱스 = **이 전략의 해석물**(피처 패널, 스코어, 백테스트 결과).

## 3. 애널리스트 리포트 · 원장 연결

두 소스의 역할이 다르고, **합쳐야 원장이 완성된다**.

| | 한경컨센서스 | 네이버 금융 리서치 |
|---|---|---|
| 작성자(애널리스트) | ✅ 리스트 컬럼에 직접 | ❌ (PDF/상세에만) |
| 목표주가·투자의견 | ✅ `skinType=business` 9컬럼 레이아웃 | 상세페이지 `div.view_info_1 em.money` |
| 종목코드 | ❌ 제목의 `종목명(005930)` 에서 정규식 | ✅ `td[0] a.stock_item` href |
| 커버리지 | 배포 동의 증권사 한정 | 넓음 |

**함정과 대응**

- `skinType` 을 빠뜨리면 **6컬럼 레이아웃**이 와서 목표주가·작성자가 조용히 사라진다.
  → 컬럼 인덱스를 믿지 않고 **`<th>` 헤더 텍스트로 매핑**하고, 헤더가 없을 때만 내용 기반 폴백.
- 적정가격 `"0"` / `"-"` 는 "목표주가 없음"이다. `int("0")` 으로 넣으면 리비전 팩터가 오염된다.
- 네이버는 body 가 **EUC-KR 인데 meta 는 utf-8 이라고 거짓말**한다 → 예외 없이 글자가 깨진다.
  → 후보 인코딩별 **한글 가독성 점수**로 선택.
- 네이버 날짜는 `YY.MM.DD` → 1926년으로 파싱되는 사고를 후처리로 교정.
- PDF 다운로드가 HTML 로그인 페이지를 200 으로 반환할 수 있다 → `%PDF-` 매직바이트 검사.
- 증권사 사명 변경(미래에셋대우→미래에셋증권, 하나금융투자→하나증권, 이베스트→LS증권 …)을
  정규화하지 않으면 **같은 애널리스트가 소속 변경만으로 다른 사람이 되어** 목표주가 리비전이 망가진다.

**왜 애널리스트 식별이 전략에 구조적으로 필요한가**
D축 `d2`(상향 리비전)는 *같은 애널리스트가 같은 종목에 이전에 제시한 목표주가*와 비교해야 한다.
애널리스트 원장이 없으면 이 지표를 만들 수 없다. 장식이 아니다.

**무결성 감사**는 연도×소스별로 애널연결률·종목코드율·목표주가율을 표로 출력하고,
대형사 10+/중소형 10+ 커버리지 충족 여부를 판정한다.

> ⚠ 두 사이트 모두 `robots.txt` 가 `Disallow: /` 다. 사용자의 명시적 지시에 따라 수집하되
> 보수적 속도로 제한하고 그 사실을 로그에 명시한다. PDF 원문은 증권사 저작물이므로
> 로컬 캐시/분석 용도로만 사용할 것.

## 5. 강건성 · 킬 기준

`R1 누수민감도 → R2 TP vs 나이브⭐ → R3 퀄리티 직교화⭐ → R4 플라시보 → R10 정책반증 →
R5 절제 → R11 팩상관 → R6 PBO/DSR → R7 레짐 → R8 하위기간 → R9 회전율·용량`

- **R1** 은 두 부분이다. **R1a**(미래수익을 신호에 주입한 고의 오염본)가 판정 기준이고,
  R1b(실제 신호 1개월 선행)는 참고다. R1b만으로는 "하네스 둔감"과 "신호에 알파가 없음"을
  구분할 수 없기 때문이다.
- **R2** 가 이 시스템의 존재 이유를 검정한다. `z(개선)×z(대가회피)` 가 `z(개선)` 단독을
  못 이기면 트레이드오프 논리 전체가 불필요한 복잡도다. **유리하게 해석하지 않는다.**
- 킬 기준(⭐) 위반 시 `KillCriteria` 로 즉시 중단하고 그대로 보고한다.
  `STOP_ON_KILL_CRITERIA=False` 로 끄지 말 것.

## 8. 알려진 한계 (숨기지 않는다)

1. **컨센서스 fwd EPS 시계열은 과거 복원이 불가능하다.** D축 `d1` 의 E 는 후행 12M 이익
   대리변수를 쓴다. 초기 구간일수록 오차가 크다. (§16.2)
2. **산업 분류는 현재 시점 분류**를 쓴다. 규모 버킷은 PIT 이지만 산업은 아니다.
   변경 빈도가 낮아 영향이 제한적이나, 완전한 C4 충족은 아니다.
3. **DART 콜드빌드는 일일 호출한도(20,000) 때문에 며칠 걸린다.** 진행률과 잔여량을 표시하고
   재실행 시 정확히 이어받는다. (§3 — 콜드빌드는 4시간 반복예산 밖)
4. **PACK-X 는 HS↔기업 매핑 테이블이 선행되어야 한다.** 5단계 파이프라인(수 주)은 자동
   구축 대상이 아니므로, 매핑이 없으면 팩이 자동 비활성화된다.
5. **하한선(§8.2)은 축 수에 민감하다.** 축 k개면 잔존율이 대략 `0.5^k`. 통합 파일보다
   팩별 단독 파일이 스펙의 "표본 붕괴 없이" 의도에 더 가깝다.
6. **이 전략은 우측 꼬리 의존적이다.** 상위 5% 종목 제외 시 성과가 사라지는지 매 실행
   측정해 출력한다. MDD 30% 초과 가능성이 높다.

# ARC-SACN — 공동커버리지 네트워크 모멘텀 (SPEC-A)

한 애널리스트가 두 기업을 **동시에 커버한다는 사실 자체**를 경제적 연결의 식별자로 쓴다.
애널리스트는 희소한 자기 시간을 배분하는 주체이므로, 두 기업을 함께 보는 선택은 그 둘이 같은
정보집합을 공유한다는 강한 증거다 (Ali & Hirshleifer, JFE 2020).

```
covered(a,i) = 1  if 애널리스트 a 가 [t-12M, t] 에 종목 i 리포트를 1건 이상 발간
w_ij(t)      = Σ_a covered(a,i)·covered(a,j)      (i≠j)
SACN_i(t)    = Σ_j w_ij(t)·r_j(t-1) / Σ_j w_ij(t)
```

## 실행 파일

`strategies/arc_sacn_shared_coverage_network.py` — **이 파일 하나로 완결**된다.
Colab / JupyterLab 한 셀에 붙여넣거나 `python <파일>` 로 실행하면

## DART 호출량 — "남은 만큼 쓴다"

이전 구현의 결함 4가지를 고쳤다.

| 결함 | 수정 |
|---|---|
| 상한을 `19_000` 으로 하드코딩하고 그 숫자를 게이트로 씀 | 상한은 표시용 힌트. 실제 정지 조건은 API 의 `status='020'`. 한도 상향 계정이면 그만큼 더 쓴다 |
| `020` 을 받고도 `exhausted` 를 게이트에 안 씀 | 020 = 하드 스톱. 이전엔 남은 작업이 전부 실제 HTTP 를 쏘고 실패했다 |
| 카운터를 **전용** 네임스페이스에 저장 | 호출량은 전략이 아니라 **API 키**에 걸린다 → 공용에 키별로 저장. 두 전략이 각자 2만건이라 착각하던 문제 |
| 날짜 경계를 컨테이너 로컬시각(UTC)으로 | DART 초기화 기준은 **KST 자정** |

그리고 애초에 **이 전략은 DART 를 거의 쓰지 않는다.** §6.3 직교화의 BM 한 항목이 전부이고,
1순위는 KRX 월말 PBR 스냅샷이다. 호출 설계는 전부 *날짜 1개 = 전종목 1호출* 스냅샷 API 다:

```
시가총액 120호출 + 펀더멘털(PBR) 120호출 + ETF/ETN 목록 12호출 ≈ 250호출로 10년치 완료
DART 는 그 스냅샷이 빈 곳만 배치(100사/호출)로 보강 → 통상 2,000건 미만
```
종목별 루프로 짜면 같은 데이터에 20배가 든다. 4시간 예산에서 2~4만 호출이 필요했던 것은
데이터가 많아서가 아니라 설계가 종목 루프였기 때문이다.

## 구글드라이브 캐시 — 절대 1원칙

기존 캐시·인덱스를 훼손하지 않는다. 약속이 아니라 **구조**로 보장한다 (TCD v2 와 동일한 Vault):
append-only JSONL 저널 · 백업 후 교체 · 내용해시 blob · **삭제 API 자체가 없음**.

```
{ROOT}/_shared/    ← 공용: 가격·리포트원장·애널리스트원장·시총·펀더멘털  (TCD v2 와 공유)
{ROOT}/arc_sacn/   ← 전용: 링크행렬·신호패널·백테스트·outputs/
```

`_shared` 를 **TCD v2 와 같은 루트로 잡아** 기존에 모아둔 리포트·가격을 그대로 재사용한다.
루트는 하드코딩하지 않고 `resolve_project_root()` 가 런타임에 결정한다 (SPEC §2.1, `/content` 금지).

## L1 수집계층 전면 재작성 — 실측 로그가 시킨 일

첫 배포본을 사용자가 윈도우/JupyterLab(파이썬 3.14, 16코어)에서 실제로 돌린 로그가 근거다.
L0(계약검정·스모크·리허설)와 계산계층은 전부 정상이었고, **소요시간과 실패의 100%가 L1 수집**에

## 3중 적대적 감사에서 나온 것 (초록불이 거짓이었던 것들)

재작성본을 다시 세 갈래(가격계층 미시 / 리서치·메타 미시 / 전체흐름 거시)로 감사했다.
가장 아픈 지적은 **"보증이 깨진 순간에 초록불이 켜진다"** 는 부류였다.

| 결함 | 왜 치명적인가 |
|---|---|
| `persist()` 가 `put_table()` 의 **반환값을 안 봤다** | `put_table` 은 쓰기 실패를 예외가 아니라 `None` 으로 알린다. 드라이브가 파일을 잡고 있으면 원장에는 "저장"으로 찍히고 감사는 **"절대원칙 점검 통과"** 를 출력했다 |
| 최대 데이터셋(`krx_ohlcv_daily`)에 **영수증이 없었다** | 감사는 `note_new_data` 등록분만 본다. 영수증이 없으면 통째로 유실돼도 감사가 **구조적으로 볼 수 없다** |
| 공용 가격표를 **이번 실행 창으로 잘라 덮어썼다** | 같은 표를 쓰는 다른 전략의 이력이 삭제된다. 삭제 API 가 없는데 삭제가 일어나는 경로 — 절대 1원칙 위반 |
| 백오프의 '지금'이 `BACKTEST_END` 였다 | 경과일수가 항상 0 → 백오프가 영원히 만료되지 않음. "1년 안에 재시도"가 실제로는 **영구 포기** |
| `_ETF_PAT` 의 `파워` 부분일치 | 파워로직스(047310) 같은 **보통주가 ETF 로 분류**되어 10년 내내 유니버스에서 사라짐. 감사표엔 "ETF 제외" 한 줄만 남는다 |
| 상장일로 요청창 하한을 좁혔다 | 폐지종목은 상장일이 '첫 스냅샷'으로 대체되므로 **생존 종목만** 사전구간을 온전히 받는다 — 생존자편향 제거 코드가 편향을 만들었다 |
| `use_cache=False` 가 쓰기를 안 막았다 | 계약검정·스모크가 매 실행 **합성 링크행렬을 사용자 드라이브에 남겼다**(삭제 API 없음) |
| `mktcap_is_approx` 를 **아무도 읽지 않았다** | 산출물엔 "근사분은 하한에서 제외"라고 적으면서 코드는 안 했다. 게다가 그 정책은 폐지종목을 전멸시켜 생존자편향을 되살린다 — 정책 자체를 바꿨다 |
| `.rev` 폴백 파일을 `get_table` 이 못 읽었다 | 백업 실패 시 피신시킨 파일이 디스크엔 있는데 영원히 안 읽힘 — 저장 성공, 재호출 실패 |
| 상세 캐시를 `itertuples` 로 읽었다 | namedtuple 이 `_detail_src` 를 `_4` 로 개명 → **2회차 실행이 100% AttributeError**. 1회차는 캐시가 없어 이 경로를 안 타므로 통과한다 |
| `np.nan` 이 애널리스트 이름이 됐다 | `nan or ""` 은 `nan` 이다 → `"nan"` 유령 애널리스트가 브로커마다 생겨 링크 행렬에 완전그래프 블록을 만든다(신호가 브로커 평균으로 붕괴) |
| K19 가 소스 문자열만 grep 했다 | `put_table` 이라는 글자만 있으면 통과. 영수증 없는 최대 데이터셋을 두고도 초록불이었다 → **런타임 프로브로 교체** |
| `PIPE.stage` 가 `BaseException` 을 삼켰다 | `critical=False` 스테이지에서 **Ctrl-C 가 무시**되고 실행이 계속됐다 |
| `LOG.table` 이 버퍼에 안 남았다 | `run_log_*.txt` 에 감사표가 통째로 빠져 있었다 — 나중에 다시 봐야 하는 게 바로 그 표들이다 |

그 외: `append_jsonl` 을 단일 `os.write(O_APPEND)` 로(드라이브 마운트에서 줄 섞임 → 인덱스 행
유실), `quiet_fds` 에 `sys.stdout/stderr` 교체 추가(주피터 IOPub 의 실제 원인은 fd 가 아니라
ZMQ 스트림이다) + `KeyboardInterrupt` 창 + 중첩 잠금, 전역 소켓 타임아웃(FDR 은 `timeout` 없이
`requests.get` 한다 → 스레드풀이 영원히 대기), 회로차단을 "성공 이력이 0인 소스"에만 적용(폐지
종목 연속 10건으로 살아 있는 소스를 끊던 문제), `adopt_scan` 의 `os.walk` 상한·벽시계, 캐시 루트
판정에 저널/파케이 존재 요구(남의 프로젝트 폴더를 덮어쓰는 경로), 윈도우 드라이브 문자 탐색
8초 예산, PDF 캐시 적중 시 전체 인덱스 스캔 제거, `exec_px` 의 종가 폴백 제거(우리 문서가
스스로 미래누수라 부른 것), KRX 시총 단위 교차검증(시총/(주식수×종가) 중앙값 이탈 시 폐기).

## 로컬·드라이브 동시 읽기 (재수집 제거)

캐시 루트를 하나만 고르면 반대편에 있는 절반을 매번 다시 받는다. **읽기는 발견된 모든
루트에서, 쓰기는 한 곳(드라이브 우선)에만** 한다. 분산 저장은 어느 쪽이 최신인지 알 수
없게 만들어 훼손의 시작이 되므로 쓰기는 반드시 단일 루트다. 계약 **K23** 이 보조 루트
읽기를 실제로 왕복시켜 검사한다.

드라이브 탐지도 강화했다 — 폴더명 매칭이 아니라 ① 구조(`_shared/index` + 저널/파케이 존재)
② 윈도우 **볼륨 레이블** ③ **DriveFS 설정** ④ 맥 CloudStorage ⑤ WSL. 그래도 못 찾으면
실행 끝에 "이 PC 에만 저장됨"을 표로 명시하고, 나중에 `GDRIVE_ROOT` 를 넣으면 지금의 로컬
캐시가 **자동으로 보조 읽기 루트로 잡혀 재수집 없이 이어진다.**

## 절대원칙 — 신규 수집물은 전부 저장되고 세션과 무관하게 재호출된다

규율이 아니라 **구조**로 강제한다.

```
note_new_data(...)     네트워크에서 새로 받은 순간 등록 (영수증)
persist(...)           유일한 저장 경로. 공용/전용 인덱스에 쓰고 원장에 기록
cache_audit()          등록됐는데 저장 안 된 것을 찾아냄 → 경고가 아니라 실패로 취급
cache_manifest()       datasets[].name + recall 코드를 남겨, 다음 세션이 이름을 몰라도 꺼내 씀
```

실행 끝에 `드라이브 캐시 원장` 표와 `cache_manifest.json` · `cache_ledger.csv` 가 나온다.
리허설(가짜 네트워크) 중에는 `persist()` 가 쓰기를 **거부**한다 — 합성 데이터가 공용 인덱스에
남으면 이후 실수집이 "그 달은 이미 있다"며 영원히 건너뛰기 때문이다(절대 1원칙 위반 경로).
계약 K17 이 이 거부를 실제로 검사한다.

## 판정은 기계적으로만

사전등록 12개 구성(§6.4) 외 변형을 추가하지 않는다. H1~H4 는 BH-FDR(q=0.10) 보정 후
§11 기준으로만 판정한다. "유망하다" 같은 표현을 쓰지 않는다.

**ACCEPT** H1·H2·H3 + PBO<0.5 + DSR>0 + 동일가중 대비 연 +3%p ·
**CONDITIONAL** H1·H2 통과 + H3 실패(페이퍼만) ·
**KILL** H1 실패 / H2 실패(업종 모멘텀 재포장) / PBO≥0.5 ·
**NOT_EVALUABLE** 표본 부족으로 분위 포트폴리오가 구성되지 않은 경우
(이 경우 PBO=1.0 같은 값이 그럴듯한 KILL 로 둔갑하는 것을 막는다)

## 알려진 한계 (숨기지 않는다)

1. **발간 시각을 두 소스 모두 제공하지 않는다.** 장중/장후 구분이 불가능하므로 전 건을 장중
   발간으로 간주하고 `knowledge_date = 발간일 + 1영업일` 로 보수화했다.
2. **업종은 현재시점 분류**다(PIT 아님). 변경 빈도가 낮아 영향은 제한적이나 완전하지 않다.
3. **관리종목·거래정지는 시점가변 PIT 공개소스가 없어 제외하지 못했다.** 제외하면 성과가
   개선되는 방향이므로 남기는 쪽이 보수적이다.
4. **1인당 유효 목표주가 개정이 적다.** EB 축소가 사전분포를 거의 그대로 돌려주면
   `highskill` 구성은 개인 스킬이 아니라 하우스/섹터 효과에 가깝다 — 결과표에 명시된다.
5. `analyst_id = sha1(broker, name)` 이므로 **이직하면 다른 식별자**가 된다. 이는 SPEC §4.2 의
   요구와 일치한다(같은 하우스에서 동시에 본다는 사실이 링크의 핵심).
