# QVF-FUNNEL v1.0 — 가치·퀄리티·수급 깔때기

한국 초소형주 3단 깔때기 퀀트 시스템. 명세서 v1.0 구현체.
백테스트 구간 **2016-08 ~ 2026-07 (10년) · 분기 리밸런싱(3/1, 6/1, 9/1, 12/1)**.

```
U-1000  PIT 시총 하위 1000 (KOSPI+KOSDAQ, 폐지종목 포함)
  └─[1차] 가치(V) / 퀄리티(Q) / 수급(F) 스코어 — 3변형 V · VQ · VQF ──→ U-200
        └─[2차] DART 하드팩트 ΔNONFIN + 애널리스트 ΔTONE(결측허용) − 배제플래그 ──→ 60~80
              └─[3차 3-A] 규칙 체크리스트 ──────────────────────────────→ 20~40 종목
```

**실행 파일: `strategies/qvf_funnel_v1.py` 하나로 완결된다.**

## 1. 캐시 — 절대 1원칙

**읽기는 여러 루트에서, 쓰기는 구글드라이브 한 곳에서만.** 약속이 아니라 구조로 보장한다.

- 쓰기 루트는 `qvf_resolve_roots()` 가 자동 탐지한다. Colab 마운트 · Windows `G:/My Drive` ·
  macOS `~/Library/CloudStorage/GoogleDrive-*` · Linux rclone 경로를 모두 훑고,
  **이미 `_shared` 인덱스가 들어 있는 폴더를 최우선으로 채택**한다 → 다른 전략(TCD 등)이
  쓰던 캐시를 그대로 이어받는다.
- `CACHE_MIRROR_ROOTS` (기본에 `D:/quant_cache` 등 포함) 는 **읽기 전용 미러**다. 이것을
  주석이 아니라 **세 겹의 구조**로 보장한다:
  1. `_wpath()` — 모든 쓰기 경로(`journal`/`idx_parquet`/`blob_dir`/`table_dir`)가 통과하며,
     쓰기루트 밖이면 `PermissionError` 를 던진다. 상속받은 어떤 코드도 미러를 쓸 수 없다.
  2. `ro_read_parquet()` — 미러는 **절대 파일을 건드리지 않는 리더**로만 읽는다.
     공용 코어의 `read_parquet_safe` 는 읽기 실패 시 파일을 `.corrupt` 로 **개명**하는데,
     Drive 의 placeholder(0바이트)·동기화 중 파일이 바로 그 실패를 낸다. 즉 정상적인
     드라이브 동작이 곧 파괴 조건이었다.
  3. `compact()` — 미러 행이 드라이브 인덱스에 섞여 들어가지 않도록 자기 루트 전용 모드로 내린다.
  계약 **Q7** 이 이 셋을 **실행으로** 검증한다(미러에 쓰기 시도 → 차단되는지, 미러의 0바이트
  파일을 읽어도 → 원본이 그대로인지).
- 미러에만 있는 테이블은 드라이브에 **없을 때만** 승격 복사한다(최신본을 과거본으로 덮을 수 없다).
- 인덱스의 진실은 append-only JSONL 저널. `index.parquet` 은 파생물이며 재생성 전 항상 백업.
  blob 은 내용해시 경로라 덮어쓰기 자체가 발생하지 않는다. **삭제 API 가 존재하지 않는다.**

```
{ROOT}/
├── _shared/     ← 공용 인덱스 (다른 전략도 그대로 재사용)
│   ├── index/{index.jsonl(원천), index.parquet(파생), _backup/, dart_quota.jsonl}
│   ├── blob/research/report_pdf/<해시>/…
│   └── table/{krx_ohlcv_daily, krx_marketcap_snapshots, dart_fnltt_raw, dart_share_counts,
│              dart_disclosures_qvf, dart_report_facts, research_report_master,
│              research_report_text, analyst_master, report_analyst_link, qvf_flow_netbuy_w60 …}
└── qvf_v1/      ← 전용 인덱스 (이 전략의 해석물)
    └── table/{l1_panel_*, qvf_report_tone, backtest_returns_*, qvf_experiment_summary}, reports/
```

## 2. DART 호출한도 — 고정 상수가 아니라 실측

OpenDART 는 **잔여 호출량을 알려주는 엔드포인트·필드·헤더를 제공하지 않는다.** 확인 가능한
신호는 한도 초과 시의 `status="020"` 뿐이다. 그래서 `DartQuota` 는:

1. 같은 키를 쓰는 **모든 전략이 공용 저널(`_shared/index/dart_quota.jsonl`)에 사용량을 append** —
   전략별 사설 카운터는 서로를 못 보고, 각자 여유 있다고 믿다가 합계로 한도를 넘긴다.
2. `020` 을 처음 만난 순간의 누적 사용량 = **그날의 실측 상한**으로 기록.
3. 과거 실측 상한은 **계획용 추정치로만** 쓰고, 소비는 서버가 실제로 `020` 을 줄 때까지 계속한다
   → 추정치 때문에 남은 호출을 놀리지 않는다.
4. 아직 실측된 적이 없으면 "미확정"이라고 표시한다. 20,000 같은 숫자를 지어내지 않는다.

계약 **Q12** 가 이 성질(하드코딩 상한으로 막지 않을 것, 공용 스코프일 것)을 소스 검사로 강제한다.

## 3. 편향 제거

| 편향 | 대응 | 강제 수단 |
|---|---|---|
| **미래누수** | 모든 테이블은 `pit_frame()` → `PITStore` (PIT 컬럼 없으면 `KeyError`). 조회는 `knowledge_date ≤ as_of` 만. 신호일 = 리밸일 **직전** 거래일, 체결 = **익** 거래일 시가. DART 는 §4대로 **접수일 + 1거래일** | Q1, Q2 |
| **생존자편향** | 폐지 종목을 PIT 스냅샷에 포함. 보유 중 폐지는 **정리매매가가 관측될 때만** 실가, 아니면 −100%. 체결가 결측 종목도 폐지 확인되면 −100% | Q3 |
| **부호 오분류** | 음수 EBIT·자본·CF 는 역수에서 최우량으로 뒤집힌다 → **셀 최하위 z 로 강제 배정**(버리지 않는다) | Q4 |
| **결측 처리 왜곡** | 리포트 없는 종목은 **관측치로 z 를 만든 뒤에** 0(중립)을 주입. 순서를 바꾸면 '리포트 보유' 자체가 신호가 된다 | Q5 |
| **과적합** | 가중치는 사전등록 고정. 선정 경로에 최적화 루틴이 없음을 소스 검사 | Q6 |
| **정렬 의존** | 동점은 명시적 키로 깬다. 행 순서를 섞어도 같은 종목이 나와야 한다 | Q8 |
| **다중검정** | 주 실험 3 + 어블레이션 4 를 한 패밀리로 BH-FDR(q=0.10) | §8.3 |
| **비용 은폐** | 비용 전/후 병기 강제. 거래세 6단계 이력 + Corwin-Schultz 실측 스프레드 + 제곱근 충격 | Q10 |

## 4. 애널리스트 텍스트 — 조용히 틀리기 쉬운 세 곳

1. **면책조항·서명부를 안 지우면 증권사 지문**이 되어, 분류기가 감성이 아니라 '어느 증권사인가'를
   학습한다. → 지웠다고 믿지 않고 **증권사 분류기 정확도가 기저율로 무너지는지 직접 측정**해서
   표로 출력한다. 그 검증이 이 설계의 전부다.
   (제거 패턴은 반드시 **문장 경계**에서 멈춘다. `[^\n]{0,400}` 로 잡으면 PDF 추출 텍스트에
   줄바꿈이 드물어 뒤따르는 실제 분석 문장까지 통째로 지운다 — 리허설이 이 버그를 잡았다.)
2. **확장윈도우의 컷오프는 발간일이 아니라 라벨 확정일**이다. 라벨이 2일 CAR 이므로
   `발간일 + 2거래일 < 경계` 여야 한다. 발간일로 자르면 경계 직전 리포트가 경계 너머를 본다.
3. **ΔTONE_resid = 0 은 z-score 이후에 주입**한다. 이전에 넣으면 결측이 다수인 구간에서
   평균이 0 으로 끌려가 리포트 보유 종목의 z 가 통째로 왜곡된다.

두 소스의 역할이 다르고 **합쳐야 원장이 완성된다**: 한경컨센서스는 작성자·목표주가를 리스트에서
바로 주지만 종목코드가 없고(제목 정규식으로 추출), 네이버는 종목코드를 확실히 주지만 작성자가
리스트에 없다(PDF 추출 의존). 증권사 사명 변경(미래에셋대우→미래에셋증권 등)을 정규화하지
않으면 같은 애널리스트가 소속 변경만으로 다른 사람이 되어 목표주가 수정률이 망가진다.

## 5. 적대적 감사가 잡아낸 것 (12에이전트 · 4관점)

설계 후 4개 관점(미래누수 / 생존자편향 / 런타임·차단 / 크래시·조용한 실패)으로 실제 소스를
읽고 실행시켜 검증했다. 아래는 **실증된 결함**이며 전부 수정 완료다.

| # | 결함 | 왜 치명적인가 |
|---|---|---|
| 1 | `read_parquet_safe` 가 **미러 파일을 `.corrupt` 로 개명** | 절대 1원칙 정면 위반. 트리거가 이상 상황도 아니다 — Drive for Desktop 의 placeholder(0바이트)나 동기화 중 파일이면 발생한다. `GDRIVE_ROOT_NAMES` 때문에 **TCD 의 드라이브 캐시까지** 미러로 잡혀 남의 전략 파일을 파괴할 수 있었다 |
| 2 | `build_quarterly_fundamentals` 의 outer merge | 주식총수는 전체 재무제표보다 자주 성공한다 → '주식수만 있고 재무는 NaN' 인 행이 생기고, as-of 조인이 그걸 집어가 `fin_cov` 를 붕괴시킨다. 그러면 §2.2 킬 기준이 **엉뚱한 메시지로** 전략을 중단시킨다 |
| 3 | 상장폐지 창이 **명목일** 기준 | 3/1 은 삼일절이라 결코 거래일이 아니다. 보유구간은 `[체결일, 다음 체결일)` 인데 판정은 `(명목일, 다음 명목일]` 이라 **분기마다 1~3일의 이음매**에서 폐지된 종목이 −100% 대신 0% 가 됐다 |
| 4 | 거래세를 **명목일**로 조회 | 세율 경계가 2019-06-03 인데 2019-06-01 은 토요일 → 그 분기 체결일이 정확히 경계일이다. 딱 한 분기에서만 20bp 과다계상되므로 아무도 눈치채지 못한다 |
| 5 | `021`(요청 오류)을 **일일한도로 기록** | 021 은 한도와 무관한데 이를 상한으로 저장하면 남은 호출을 전부 못 쓰고, 그 거짓 상한이 **공용 저널에 박혀 다른 전략까지** 오염시킨다 → 확인 호출로 020 을 확증한 뒤에만 기록 |
| 6 | `DART_DAILY_LIMIT` 이 **19,000 으로 되돌려짐** | 공용 코어가 조립 순서상 헤더보다 뒤에 있어 헤더 값을 이긴다. 사용자가 명시적으로 거부한 값이 살아 있었고 계약 Q12 는 선언만 봐서 통과시켰다 → **실효값**을 검사하도록 변경 |
| 7 | Phase 0 표가 **하지 않는 조치를 광고** | "미달 시 행동: F축 비활성" 이라 적어놓고 `PHASE0` 을 아무도 읽지 않았다 → 게이트를 §9 판정에 실제로 연결 |
| 8 | 정형문구 제거 패턴이 `[^\n]{0,400}` | PDF 추출 텍스트는 줄바꿈이 드물어 면책조항 뒤의 **실제 분석 문장까지** 삭제했다(테스트 반환 길이 0) |
| 9 | `.map()` on category | `downcast` 가 `code` 를 category 로 바꾸면 `.map()` 결과도 category 가 되어 날짜 비교가 `TypeError`. 하필 폐지 처리 경로였다 |
| 10 | BH-FDR 이 **양측 p값** | `t = −4`(강한 **음의** 알파)가 `p ≈ 0.0001` 로 '✔ 유의' 로 찍힌다. 손실이 유의하다는 뜻인데 정반대로 읽힌다 → 단측('알파>0') |
| 11 | Corwin-Schultz 가 `(t, t+1)` | `signal_date` 에서 읽는 스프레드가 **체결일의 고저**를 포함 → 비용 모델에 1일 미래정보. `(t-1, t)` 로 변경 |
| 12 | 선정 0종목 분기를 **공짜 청산** | 전량 청산에 비용 0, 그 분기 보유분 수익은 증발. §3.3 상 정상 발생 가능한 경로다 |
| 13 | 공시 이벤트를 `0.0` 으로 초기화 | '스윕 안 함'과 '스윕했는데 해당 없음'이 구별되지 않는다 → 원장이 덮은 구간에서만 0, 나머지는 결측 |

계약 **Q3·Q7·Q12** 는 위 결함들을 재현하는 테스트로 강화되어, 같은 실수가 재발하면 실데이터
수집 전에 실행이 멈춘다.

## 6. 알려진 한계 (숨기지 않는다)

1. **PIT 관리종목·투자주의환기·거래정지 이력은 공개 API 로 소급 조회가 불가능하다.** 현재 명단을
   과거에 적용하면 그 자체가 미래누수이므로 적용하지 않았다. 대신 PIT 로 확인 가능한
   완전자본잠식·4분기연속영업적자·감사의견 강조사항을 3-A 에서 쓴다 — **근사이며 동일하지 않다.**
2. **유동주식 비율의 PIT 시계열이 없다.** 발행주식수에서 자기주식만 차감한 근사 유동시총을
   F축 분모로 쓴다. 대주주·우리사주 물량이 빠지지 않아 유동시총이 과대추정되는 방향이다.
3. **EPS 컨센서스 수정률의 과거 시계열은 복원 불가**라 ΔTONE 직교화 설명변수에서 제외했다.
   목표주가 수정률로 일부 대체했으나 동일하지 않다.
4. **구형 DART 공시는 스캔 PDF 비중이 높아 기계판독이 불가능하다.** `dart_parse_rate` 를
   '섹션 없음 / 판독 불가(스캔) / API 무응답' 으로 분해해 보고한다 — 셋은 원인이 다르다.
   스캔본 비중이 높으면 정규식을 고쳐도 개선되지 않는다.
5. **호가 스프레드 실측치가 없어** Corwin-Schultz 고가/저가 추정량을 쓴다. 초소형주에서 상향
   편의가 있고 음수 추정치가 잦다(0 으로 절단).
6. **DART 콜드빌드는 일일 한도 때문에 며칠 걸린다.** 진행률과 잔여량을 표시하고 재실행 시
   정확히 이어받는다 (콜드빌드는 §0.5 의 4시간 예산 밖).

```bash
python3 tools/build_qvf.py    # build/q*.py + 공용 코어 → strategies/qvf_funnel_v1.py
python3 tools/smoke_qvf.py    # 조립본을 SMOKE 모드로 실제 실행해 검증
```

빌더는 문법 검사 · 최상위 이름 중복 검사 · **최상위 '정의 전 참조' 검사**를 수행한다
(마지막 것은 조립 순서 사고의 대표 증상이며 문법 검사로는 잡히지 않는다).
