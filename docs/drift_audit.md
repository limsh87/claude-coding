# 하향 드리프트 전수감사

> **질문**: 서로 무관한 알파 아이디어를 10여 개 시험했는데 하나같이 성과가 안 나온다.
> 특히 FPU·HS코드 통관 데이터처럼 독창적이고 경제적 근거가 탄탄한 것도 마찬가지다.
> 아이디어가 전부 틀린 것인가, 아니면 **모든 아이디어가 공유하는 하네스**에 하향 편향이 있는가?

> **답**: 하향 편향이 있다. 실측 **연 −4.00%p (95%CI −5.2 ~ −2.8)** 이고,
> 시뮬레이션이 못 잡는 배당 누락을 더하면 실질 **연 −5.5 ~ −6%p** 다.
> 10%p 대는 아니다. 그런데 **그게 문제가 아니다** — 진짜 문제는 킬게이트다.
> **총수익 기준 연 7% 미만의 알파는 R3 가 전부 죽인다.** 팩터 알파의 통상 크기는 연 2~5% 다.

재현: `python3 tools/drift_audit.py` (오차범위·알파 통과율까지 보려면 `--deep`, 수 분 소요)

## 0. 감사 방법 — 알파를 0으로 못박고 엔진만 돌린다

의심이 "엔진에 있다"이므로, **엔진에 알파가 0인 신호를 넣고 무엇이 나오는지** 본다.

- `build/41_backtest.py` 의 함수를 **복제·수정 없이 그대로 `exec`** 한다. 상수도
  `build/00_header.py` 에서 정규식으로 읽어온다 (하드코딩하면 감사 자체가 거짓말이 된다).
- 신호는 미래수익과 **통계적으로 완전히 독립**한 AR(1) 난수 → 참 알파는 정확히 0.
- 정답값 = 적격(거부권·하한선 통과) 유니버스 동일가중 수익. 알파가 0이면 여기에 붙어야 한다.
- 700종목 × 120개월. 신호 자기상관 0.95 (펀더멘털 신호의 현실적 값).

시드 40개 평균:

```
인공 드리프트   월 -0.340%p ± 0.052   →   연 -4.00%p   [95%CI -5.18 ~ -2.81%p]
  그중 비용     월 +0.283%p           →   연 +3.45%p    ← 결정론적, 표본오차 없음
  나머지        월 -0.057%p           →   현금끌림 등 (투자비중 95.2% · 평균 9.3종목)
```

**CAGR·Sharpe 절대값은 여기 싣지 않는다.** 합성 시장팩터 120개월 표본평균의 노이즈와
8종목 집중의 변동성 드래그(σ²/2 차이 ≈ 연 1%p)가 섞여 엔진 귀책분을 부풀리기 때문이다.
같은 데이터 위에서 잰 **드리프트만이 엔진에 귀속되는 값**이다.

두 가지 방향의 보정이 더 필요하다:

- **과소평가 방향**: 이 합성시장은 표본평균이 음수라 **현금끌림이 오히려 도움이 됐다.**
  실제 시장(연 +6%)에서는 반대로 작용한다 (§5).
- **미포함**: 배당 누락(§3, 연 −1.5~2.0%p)은 합성 데이터에 배당이 없으니 애초에 안 잡힌다.

→ **실질 드리프트 연 −5.5 ~ −6%p** 로 본다.

## 1. ⭐ 최우선 — R3 킬게이트가 순수익을 총수익 팩터에 회귀한다

`build/50_robust.py:185-232`


좌변만 비용을 뺐고 우변은 안 뺐다. 그래서 **회귀 절편(=알파)이 월 0.287%p, 연 3.49%p

**실측** — 신호에 진짜 예측력을 심어 놓고 엔진 출력을 봤다 (시드 20개, `--deep`):

| 심은 알파(연) | 엔진 총수익 초과 | 엔진 순수익 초과 | R3 이 읽는 알파 | R3 판정 |
|---|---|---|---|---|
| 0.0% | −1.49% | −4.86% | −4.86% | ✘ KILL |
| 2.5% | +0.32% | −3.10% | −3.10% | ✘ KILL |
| 5.0% | +2.17% | −1.32% | −1.32% | ✘ KILL |
| 7.5% | +4.05% | +0.50% | +0.50% | 통과 가능 |
| 12.5% | +7.89% | +4.23% | +4.23% | 통과 가능 |

**총수익 기준 연 5% 짜리 진짜 알파도 KILL 이다.** 통과선은 연 7% 대에 있고,
`alpha_m > 0` 만이 아니라 `t > 1.5` 까지 요구하므로 실제 통과선은 그보다 더 높다.

`STOP_ON_KILL_CRITERIA = True` 가 기본값이고 README 는 "끄지 말 것"이라고 못박았다
(`build/00_header.py:156`). **팩터 알파의 통상 크기는 연 2~5% 다.**
즉 정상적인 크기의 알파는 이 스위트에서 **구조적으로 발견 자체가 불가능하다.**
"경제적 근거는 탄탄한데 전부 죽는다"의 가장 직접적인 기계적 원인이 이것이다.

> 표에서 '총수익 초과'가 심은 알파보다 작은 것(예: 12.5% → 7.9%)은 상위 5% 만 사는
> 선정 손실이라 정상이다. 반면 **'총수익 초과'와 '순수익 초과'의 간격 ≈ 3.4%p 는 전부 비용**이고,
> R3 는 좌변(순)에서만 이걸 빼고 우변(총)에서는 안 뺀다. 간격이 그대로 절편에 남는다.

이건 성능 저하가 아니라 **판정 오류**다. R2·R4 는 양팔이 같은 기준이라 공정하다 —
R3 만 비대칭이다.

**고칠 곳**: `bt["returns"]["ret_gross"]` 로 회귀하거나(엔진이 이미 저장하고 있다),
팩터 쪽에도 동일 비용을 물리거나, 둘 중 하나. 지금은 사과와 오렌지를 비교하고 있다.

## 2. 슬리피지 계수가 이론값의 약 7배

`build/41_backtest.py:22,34-39`

```python
SLIPPAGE_K = 0.10
def slippage(trade_krw, adv_krw):
    if not np.isfinite(adv_krw) or adv_krw <= 0:
        return 0.02                                   # ← 무조건 200bp
    part = min(1.0, abs(trade_krw) / adv_krw)
    return float(SLIPPAGE_K * math.sqrt(part))
```

제곱근 충격법칙의 표준형은 `impact = Y · σ_daily · √참여율` (Almgren 등, Y≈0.5~1.0)이다.
이 코드는 **σ 항이 통째로 빠져 있고**, 그 자리에 0.10 이 들어가 있다.
한국 소형주 σ_daily ≈ 2.5%, Y=0.6 이면 계수는 **0.015** 여야 한다.

계좌가 3,000만원이라 주문 자체가 아주 작은데도:

| 20일 평균거래대금 | 비중 | 주문금액 | 참여율 | **모델** | 현실 추정 |
|---|---|---|---|---|---|
| 3억 (V6 하한) | 12% | 3,600,000원 | 1.2000% | **109.5bp** | 16.4bp |
| 20억 (중앙값) | 12% | 3,600,000원 | 0.1800% | **42.4bp** | 6.4bp |
| 20억 (중앙값) | 4% | 1,200,000원 | 0.0600% | **24.5bp** | 3.7bp |
| 1000억 (대형주) | 12% | 3,600,000원 | 0.0036% | **6.0bp** | 0.9bp |
| 거래대금 결측/0 | — | — | — | **200.0bp** | — |

거래대금 20억 종목에 360만원 주문은 실무적으로 체결 즉시·호가 한 틱 안쪽이다.
모델은 42bp 를 물린다.

계수만 바꿨을 때 (그 외 전부 원본 그대로):

| SLIPPAGE_K | 월비용 | 연비용 | 알파0 드리프트/년 |
|---|---|---|---|
| **0.100 (현재)** | 0.287% | **3.49%** | **−3.92%** |
| 0.050 | 0.175% | 2.12% | −2.69% |
| 0.025 (Almgren 상한권) | 0.119% | 1.44% | −2.07% |
| 0.015 (이론값) | 0.097% | 1.17% | −1.82% |
| 0.000 | 0.064% | 0.77% | −1.45% |

시드 15개 평균으로 다시 재면:

```
SLIPPAGE_K=0.100 (현재)  → 총 거래비용 연 3.54%
SLIPPAGE_K=0.015 (이론)  → 총 거래비용 연 1.19%
──────────────────────────────────────────────
슬리피지 과대계상분          연 2.35%p   ← 순수 인공손실
정당한 거래비용             연 1.19%p   ← 실제로 나가는 돈 (수수료·거래세·현실 슬리피지)
```

**계수 하나 고치는 것만으로 연 2.35%p 가 돌아온다.**
`return 0.02` 폴백도 문제다 — 데이터 결측을 200bp 손실로 환산하고 있고, 어디에도 기록되지 않는다.

## 3. 배당이 수익률에 전혀 들어가지 않는다

`build/11_ingest_price.py:426`

```python
monthly["fwd_ret"] = (nxt_px / monthly["exec_px"] - 1.0).where(adjacent)
```

`exec_px` 는 순수 가격이다. 배당은 **피처로만** 존재하고(`dividend_paid_ttm`,
PACK-C 의 `payout`) 수익률 계산에는 한 번도 들어가지 않는다. 코드베이스 전체에
배당 재투자·총수익 처리가 없다 (`grep -rn "배당\|dividend" build/` 로 확인).

가격 소스(pykrx `adjusted=True`, FDR, 네이버 차트)는 액면분할·무상증자는 보정하지만
**현금배당은 어느 것도 보정하지 않는다.** KOSPI 배당수익률은 2020~2025 년 평균 약 2.0~2.3%,
KOSDAQ 약 1.0~1.5% 다. → **연 1.5~2%p 의 순수 하향 편향.**

그리고 이건 단순한 레벨 이동이 아니다:

- **PACK-C 는 정의상 "환원↑" 기업, 즉 배당을 늘린 기업을 고른다.** 그 기업의
  배당을 버리고 성과를 잰다. 신호와 상관된 편향이라 알파를 정확히 그만큼 깎는다.
- 질적 전환에 성공한 기업은 배당을 개시·증액하는 경향이 있으므로 전 팩에 같은 방향으로 작용한다.

`report_performance` 의 벤치마크(KS11/KQ11)도 가격지수라 **초과수익 표는 공정**하다.
그러나 CAGR·Sharpe·MDD·그리고 **R3 의 알파**는 전부 과소평가된다.

`HOLD_MAX_MONTHS = 24` 이고 README §8-6 은 "이 전략은 우측 꼬리 의존적"이라고 명시하는데,
실제 실효 보유는 **3~5개월**이다. 우측 꼬리는 정의상 오래 들고 있어야 나오는 것이므로,
설계 의도와 엔진 동작이 정면으로 충돌한다.

원인은 청산 게이트다 (`build/41_backtest.py:42-57`):

```python
return not (de > 0 and dm < de)      # dm >= de 이면 청산
```

`dm >= de` = **가격이 이익을 따라잡는 순간 매도**. 주석은 이걸 "알파 소진(원래 의도한 청산)"
이라고 부르지만, 실제 효과는 **오르기 시작한 종목을 정확히 그 시점에 파는 것**이고,
반대로 `de > 0 and dm < de` 인 동안은 **가격이 계속 뒤처지는 종목을 계속 들고 있는 것**이다.
성과가 좋은 쪽을 자르고 나쁜 쪽을 남기는 규칙이 코드로 박혀 있다.

비용 문제이자 수익분포 문제다. 24개월 보유상한은 사실상 한 번도 도달하지 않는다.

## 5. 보유종목이 9개 미만이면 자동으로 현금이 남는다

|---|---|---|---|
| 5 | **60.0%** | **40.0%** | 12.0% ~ 12.0% |
| 6 | **72.0%** | **28.0%** | 12.0% ~ 12.0% |
| 7 | **84.0%** | **16.0%** | 12.0% ~ 12.0% |
| 8 | **96.0%** | 4.0% | 12.0% ~ 12.0% |
| 9 | 100.0% | 0.0% | 10.4% ~ 12.0% |
| 25 | 100.0% | 0.0% | 0.0% ~ 12.0% |

종목당 상한 12% × 9종목 = 108% 이므로, **9종목 미만이면 산술적으로 100% 를 채울 수 없다.**
water-filling 이 전 종목을 상한에 붙여 놓고 나머지를 0% 현금으로 남긴다.
`size_positions` 는 이 상태에서 `w.sum() > 1.0` 분기에 들어가지도 않아 조용히 통과한다.
로그·성과표 어디에도 투자비중이 나오지 않는다.

**보유종목 수는 구조적으로 작다.** `build/41_backtest.py:153`:

```python
k = int(max(PORTFOLIO_MIN_NAMES, min(PORTFOLIO_MAX_NAMES, round(len(elig) * top_pct))))
```

`elig` 는 이미 거부권·하한선을 통과한 잔존분(로그상 3~10%)인데 여기에 다시 5% 를 곱한다.
`k > 5` 가 되려면 `len(elig) ≥ 100` 이어야 하므로 대부분의 달에서 **k 는 5에 고정**된다.
README 는 "신호 상위 5% 진입"이라고 쓰여 있지만 실제로는 상위 5% 의 상위 5% ≈ **상위 0.3%** 다.

부작용 두 가지가 더 있다:
1. 전 종목이 12% 로 같아지므로 §8.5 "신호 강도 기반 사이징"은 **실전에서 한 번도 작동하지 않는다**.
2. 5~8종목 포트폴리오의 월수익 표준오차는 Sharpe 추정을 사실상 무의미하게 만든다.

## 6. 상장폐지를 사유 구분 없이 일괄 −100% 처리한다

`build/41_backtest.py:205-207` · `build/20_pit.py:242-244`

```python
if dl is not None and pd.notna(dl) and m < dl <= m + pd.offsets.MonthEnd(1):
    fr = -1.0 if not np.isfinite(fr) else fr
```

`security_master` 에 **폐지 사유 필드가 아예 없다**(`SEC_MASTER_COLS` 확인). 그래서
부실 상장폐지와 아래가 전부 같은 −100% 로 처리된다:

- M&A 피합병 (주식교환 — 주주는 인수기업 주식을 받는다)
- 자진 상장폐지 **공개매수** (통상 시장가 대비 프리미엄)
- 지주회사 전환 / 인적분할 후 재상장 (구 코드 소멸, 신 코드 배정)

맞히면 −100% 로 채점된다.

다만 정직하게 말하면, **실측 영향은 작다**. 보유가 8종목 남짓이라 10년간 조우 기대값이
1건 안팎이고, 널 테스트에서 유의한 차이가 잡히지 않았다(연 0.2% 미만). 개념적 결함이고
꼬리 위험이지, 지금 성과를 설명하는 주범은 아니다.

한편 폐지일 추정 경로(`build/10_ingest_universe.py:571-573`,
`snap_last + MonthEnd(1)`)는 스냅샷 수집이 한 달 실패해도 폐지로 간주하므로,
**데이터 공백이 −100% 로 환산될 수 있는 경로**가 열려 있다.

## 7. 모든 팩에 곱해지는 U 가 사실상 음(−)의 6개월 모멘텀이다

`build/21_axes.py:144-150` · `build/40_score.py:182`

```python
P["dlog_E"] = g("E_proxy").transform(lambda s: dlog(s, 6))   # TTM 순이익
P["dlog_P"] = g("close").transform(lambda s: dlog(s, 6))     # 6개월 가격
P["dlog_M"] = P["dlog_P"] - P["dlog_E"]
P["d1"] = -P["dlog_M"]                                       # = dlog_E - dlog_P
...
Signal = E.fillna(0) * U * VETO * FLOOR                      # U 는 전 팩에 곱해진다
```

`U = rank_pct(mean(z(d1), z(d2), z(d3), z(d4)))` 인데 d2·d4 는 컨센서스 원장이 필요하고
(README §8-1 이 "과거 복원 불가"라고 명시), d3 는 pykrx 수급이 필요하다. **이 셋이 없으면
U ≈ rank(d1) = rank(6개월 이익증가 − 6개월 가격상승)** 이 된다.

즉 어떤 팩을 붙이든 **"최근 6개월 주가가 덜 오른 종목"에 대한 곱셈 게이트**가 항상 걸린다.
이건 전략의 명시적 논지("시장이 아직 자본화 안 함")이므로 버그는 아니다. 그러나:

- 팩마다 독립적인 알파를 재려 해도 **공통 인자 하나가 전부에 곱해지므로 팩 간 성과가 서로 닮는다.**
  10개 아이디어가 "하나같이" 안 나오는 현상과 일치한다.
- 이 로딩이 얼마인지 **어디서도 측정되지 않는다.** R3 는 `f_mom = pct_change(12)` 로
  12개월 모멘텀만 통제하고 6개월은 통제하지 않는다.
- 부작용: `dlog_E` 는 순이익이 t 와 t−6 에서 **모두 양수**여야 계산된다(`dlog` 정의).
  적자 기업은 d1 이 NaN → d2/d3/d4 도 없으면 `U.fillna(0)` → **Signal = 0**.
  흑자기업 필터가 조용히 걸려 있고 감쇠 감사표에는 잡히지 않는다.

권고: 버그가 아니므로 고치라는 게 아니라, **U 단독 성과와 6개월 모멘텀 로딩을 따로 출력**해야
팩 고유 알파와 이 공통 게이트를 분리할 수 있다.

## 8. 성과지표 자체가 보수적으로 치우쳐 있다

`build/41_backtest.py:240,254`

```python
cagr = eq[-1] ** (1 / years) - 1
vol  = r.std(ddof=1) * math.sqrt(12)
"Sharpe": (cagr - rf) / vol
```

분자가 **기하평균(CAGR)** 인데 표준 Sharpe 는 산술평균을 쓴다. 차이는 변동성 드래그
`≈ σ²/2` 이고, 월 5~6% 변동성(=연 18~21%)이면 **연 1.6~2.2%p**, Sharpe 로 약 **0.10** 이다.
또 `rf = 0` 이라 현금 부분(§5)은 이자도 못 받는다.

버그는 아니지만 위 1~5 와 **같은 방향**으로 쌓인다.

> 여기에 배당(시뮬 미포함)과 실제 시장의 현금끌림을 더하면 위 범위가 된다.
> **10%p 대의 드리프트는 아니다.**

별도 항목 (수익이 아니라 **판정·지표**가 깎이는 것):

| # | 항목 | 크기 | 성격 |
|---|---|---|---|
| 1 | **R3 킬게이트 비대칭** | **총수익 알파 연 7% 미만 전부 KILL** | **판정 오류 — 실행 중단** |
| 8 | CAGR 기반 Sharpe · rf=0 | Sharpe −0.10 | 지표 선택 |

**결론은 드리프트 크기가 아니라 #1 이다.** 실현 수익 −5%p 도 팩터 알파(연 2~5%)와

KILL 로 판정하고 실행을 중단시킨다는 것**이 "10여 개가 하나같이 죽었다"의 직접 원인이다.

## 10. 왜 기존 검정들이 이걸 못 잡았나

이 코드베이스는 감사 장치가 촘촘하다(C1~C12, R1~R11). 그런데도 통과한 이유:

- **R1a(하네스 민감도)** 는 미래수익을 주입해 Sharpe 가 **오르는지**만 본다.
  드리프트는 오염본·정상본 **양쪽에 똑같이** 걸리므로 Δ에서 상쇄된다.
  R1a 는 통과하면서 −4%p/년 드리프트가 남는다.
- **R2·R4** 는 양팔 모두 같은 엔진을 타므로 공정하다 — 그래서 드리프트를 못 본다.
- **R3** 만 한쪽이 순수익, 한쪽이 총수익이다. 유일한 비대칭 지점이 하필 킬게이트다.
- **"알파 = 0 일 때 0 이 나오는가"** 를 확인하는 널 테스트가 스위트 전체에 없다.
  R1~R11 은 전부 *상대* 비교이고, **절대 수준 편향을 잡는 검정이 하나도 없다.**

`tools/drift_audit.py` 가 그 빠진 검정이다. 회귀 테스트로 상시 걸어둘 것을 권한다:
알파 0 신호를 넣었을 때 드리프트가 연 1%p 를 넘으면 실패.
