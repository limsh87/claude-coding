# ARC-AAR — 애널리스트 주의 재배분 (Analyst Attention Reallocation)

한국 애널리스트 리포트의 **메타데이터만** 사용하는 횡단면 퀀트 전략.
명세서 SPEC-C / ARC-AAR 구현체. 백테스트 구간 **2016-08 ~ 2026-07 (10년)**.

> **애널리스트가 무엇을 말했는지는 전혀 읽지 않는다.**
> 매도의견 비중이 사실상 0이고 목표주가가 제도적으로 상향 편향된 시장에서,
> "무엇을 말했는가"를 읽는 모든 팩터는 **검열된 분포** 위에서 작동한다.
> 대신 고정된 주의 예산(커버 15~25종목)을 **어디에 재배분했는가**만 본다.
> 주의 배분은 검열되지 않는다.

## 2. 신호

```
share(a,i,t) = reports(a,i,t) / N(a,t)                    N(a,t)<3 → 셀 전체 결측
base(a,i,t)  = Σ_{t-12..t-1} reports / Σ_{t-12..t-1} N     ΣN<12  → 셀 전체 결측
EA           = share − base
             → 경험적 베이즈 축소 (해석적 분산 + tau² 3단 계층, 자유도 0)
             → §6.3 기계적 발간 통제회귀 잔차 = VAS
AAR_pos(i,t) = Σ_a ω(a,t)·VAS(a,i,t) / Σ_a ω(a,t)          ω ∈ {1, N(a,t), 커버종목수}
AAR_neg(i,t) = −[1.0·V-DROP + 1.5·H-EXIT] / 직전 커버 로스터   치역 [−1.5, 0]
AAR_total    = z(AAR_pos) + λ·z(AAR_neg)
```

### 왜 §6.3 통제회귀가 전부인가

통제하지 않은 원신호는 **그냥 실적시즌 달력**이다. 실적발표월·신규커버개시·지수이벤트·
공시건수와 섹터×월·애널리스트 고정효과를 흡수하고 남은 잔차만 "자발적" 주의다.
실측에서 이 통제가 EA 분산의 상당 부분을 설명한다 — 즉 원신호의 대부분이 기계적이었다.

**통제를 성실히 했는데 신호가 사라진다면 그것이 정답이다.** 통제를 약화시켜 신호를
되살리려는 모든 시도는 이 프로젝트의 실패다.

### 음(−) 신호 — 이 전략의 차별점

공매도 제약과 매도의견 부재로 한국에서 음의 신호는 극히 희소하다. 커버리지 철회가
사실상 유일한 관측 경로인데, 거기엔 두 종류가 섞여 있다. 하우스의 커버 애널 수 변화
Δn 이라는 **단일 단조 규칙**으로 가른다:

| 분류 | 판정 | 가중 |
|---|---|---|
| `H-EXIT` | 그 증권사에서 이 종목을 커버하는 사람이 아무도 없음 | 1.5 |
| `V-DROP` | 하우스는 계속 커버하나 인원 감소 = **재직 중인데 이 종목만 끊음** | 1.0 |
| `HANDOFF` | 하우스 커버 인원 불변(승계) — **철회가 아니다** | 0.0 |
| `M-EXIT` | 애널리스트가 원소속에서 사라짐 (이직·퇴사) | **분자 제외 · 플라시보군** |
| `CENSORED-*` | 소스단절·합병창·폐지·동일인판정불가 | 전량 제외 |

**M-EXIT 에서도 효과가 나오면 인과분해는 실패**이고, 신호는 그냥
"커버리지 감소 = 소외주"의 재발견이다. R5 가 이것을 등가성 검정(TOST)으로 정면 검정한다.
표본이 부족하면 '통과'가 아니라 **판정불가**로 낸다.

| `fdr_krx_data_cache` `listing/delisting` | 전체 폐지 이력 + 사유 + 승계종목 | 폐지 수익률의 승계/전손 분기 |

| 한경컨센서스 + 네이버 리서치 | 리포트 원장 (analyst, broker, ticker, date) | robots.txt Disallow — 보수적 속도 |

### `marcap` 이 한 번에 해결하는 것

- **PIT 유니버스** — 날짜별 단면이라 그날 실제 거래된 종목만 들어 있다
- **생존자편향** — 폐지 종목이 폐지일까지 존재하다 사라진다. **구조적으로 제거됨**
- **PIT 시가총액** — `Marcap == Close × Stocks` 오차 0 (실측). 시총 하위 1000 압축의 근거
- **실거래대금** — `close × volume` 근사가 필요 없다
- **수정주가** — `ChangesRatio` 가 KRX 공식 수정등락률

> ⚠ `Close` 는 **무수정 원주가**다(삼성전자 2018-05-04 분할일 raw pct_change −98.04%,
> `ChangesRatio` −2.08%). 수익률에 `Close` 비율이나 **`Marcap` 비율을 쓰면 안 된다** —
> `Marcap` 비율에는 주식수 변동이 섞여 유상증자일에 상방 편의가 생긴다. `Marcap` 은 랭킹 전용.
> 역수정 검산: 삼성전자 2016-01-04 → **24,101** (이론 24,100).

## 4. 캐시 — 절대 1원칙 + 전면 캐시

**기존 캐시·인덱스를 훼손하지 않는다.** 약속이 아니라 **구조**로 보장한다:
append-only JSONL 저널 · index.parquet 은 백업 후 교체 · blob 은 내용해시 경로 ·
기존 파일은 이동 없이 경로만 등록 · **삭제 API 자체가 없다.**

재실행 시간을 줄이는 3계층:

| 계층 | 대상 | 효과 |
|---|---|---|
| ① HTTP 응답 캐시 | 모든 GET/조회 POST | 같은 URL+파라미터는 **두 번 다시 네트워크에 안 나간다**. 과거 구간은 TTL 무시 영구 재사용 |
| ② 원천·정제 테이블 (`_shared`) | 가격·리포트원장·애널리스트원장·공시 | **다른 전략이 그대로 재사용**. 형제 네임스페이스까지 읽는다 |
| ③ 파생 메모 (`arc_aar`) | 주의패널·VAS·철회분류·백테스트 | 입력 지문이 같으면 **계산 자체를 건너뜀** |

지문 = `sha1(이름 + 관련 설정 + 입력 데이터 요약)`. 입력이나 설정이 바뀌면 자동으로 새 지문이
되어 재계산되므로 "캐시가 낡아서 틀린 결과"가 구조적으로 불가능하다. 캐시를 지울 필요도 없다.

### 일봉을 두 번 받지 않는 구조

종전 설계는 종목당 HTTP 1회(약 3,000종목 × 폴백체인)였고, 완전 캐시 상태에서도
"무엇이 캐시에 있는지" 판단하는 데만 십수 분이 걸렸다.
현재는 **연도 parquet 11개**로 전 종목·전 기간을 받고, 그마저 HTTP 캐시에 남아
두 번째 실행부터는 네트워크 0회다. 종목 루프가 사라지면서 그 비용이 원인째 소멸했다.

## 5. API 호출량 — 하드코딩하지 않는다

이전 설계는 한도를 19,000 으로 미리 못박고 그 숫자에 닿으면 멈췄다. 실제 한도는
계정·시점에 따라 다르고 이미 쓴 양도 알 수 없으니 그 숫자엔 근거가 없다.

현재 동작:
- 오늘 사용량을 드라이브에 영속 기록 → 재실행/다른 노트북에서 이어받음
- **실제로 `status=020`(한도초과)이 올 때까지 멈추지 않는다**
- 020 이 온 시점의 사용량을 **관측된 실제 한도로 학습**해 다음 실행의 잔여량 표시에 사용
- 진행 중 잔여량을 계속 로그에 표시

그리고 애초에 요구량이 작다. 이 전략이 DART 를 쓰는 곳은 실적발표월과 공시건수 두 가지뿐이고,
둘 다 시장 전체를 날짜로 훑는 스윕이라 **10년 콜드빌드가 2,000~4,000 호출**이다.
(이전 세대가 한도를 태운 건 회사×분기 재무제표를 단건으로 받았기 때문이다)

| 편향 | 대응 |
|---|---|

| **생존자편향** | marcap 일별 단면이 구조적으로 제거. 폐지 수익률은 사유별로 승계(합병→사건 제외) / 전손(−100%) 분기 |
| **선택편향** | 유니버스 감쇠 감사표로 어느 게이트에서 표본이 붕괴하는지 매 실행 출력 |

| **과적합** | 사전등록 격자 12개 고정(계약검정이 소스로 강제) · PBO(CSCV 정식) · DSR(시행 24회) |
| **다중검정** | H1~H5 에 BH-FDR(q=0.10). "다섯 개 중 하나 통과"를 성공이라 부르지 않기 위한 장치 |

## 8. 검증 게이트

**계약 자동검정 15종** (전부 실측으로 재현된 실패를 고정한 것 — 실패 시 즉시 중단):
PIT 강제 · 날짜 규약(KST) · EB 축소 단조성 · FE 흡수(싱글턴·NaN) · 결측채움 금지 ·
사전등록 고정 · BH-FDR · 철회 분류 · 횡단면 통계 · 결정성 · 코드 정규화 · 파서 회귀 ·
병합 멱등성 · 폐지 분기 · 통계 커널

**합성 스모크** — 신호를 명시적으로 심고 하네스가 그것을 탐지하는지 확인한다.
이게 없으면 실데이터에서 "알파 없음"이 나와도 전략 탓인지 배관 탓인지 구분할 수 없다.

**강건성 R1~R10**: 블록 부트스트랩 · PBO(CSCV) ⭐ · DSR ⭐ · 워크포워드 ·
**M-EXIT 플라시보(TOST)** ⭐ · 이벤트스터디 CAR · 비용 민감도(0/기본/2배) ·
누수 민감도(확장창 vs 전기간) · 레짐·하위기간 · **나이브 대비** ⭐

> **R10 이 이 시스템의 존재 이유를 검정한다.** §6.3 통제회귀·§6.2 축소추정·§6.5 인과분해를
> 다 하고도 "단순 리포트 건수 증가"를 못 이기면 그 복잡도 전체가 불필요하다는 뜻이다.
> KOSPI 를 이기는 것은 아무것도 증명하지 못한다 — 소형주 프리미엄일 수 있다.

### 수용/폐기 (§11, 사전 확정 · 사후 변경 금지)

- **ACCEPT**: H1 ∧ H5 ∧ H2 (BH-FDR 후) ∧ M-EXIT 플라시보 통과 ∧ PBO<0.5 ∧ DSR>0 ∧ 동일가중 대비 연 +3%p
- **CONDITIONAL**: H1 통과 + H5 실패 → 컨센서스 개정의 느린 대리변수. **독립 배분 금지**
- **KILL**: H1 실패 / 통제 후 신호 소멸 / M-EXIT 플라시보 실패 / PBO≥0.5 / 나이브 대비 우위 없음
- **INCONCLUSIVE**: 판정불가 항목이 남음. **표본 부족을 '통과'로 읽지 않기 위해 의도적으로 미판정**

## 9. 에러 국소화

모든 연산은 `PIPE.stage(...)` 안에서만 돈다. 실패하면 자동 출력되는 것:
실패 지점(스테이지·계층·경과) · 직전 입출력 스냅샷(몇 행이 들어오고 나갔는지, PIT 컬럼 유무) ·
**한글 진단 힌트**(예외 패턴 → 원인·조치) · 트레이스백 마지막 12줄.

실행 끝에는 스테이지 요약 · **데이터 흐름 원장(I/O LEDGER)** · PIT 저장소 상태 ·
HTTP 감사(캐시 적중률 포함) · 런타임 감사 · 데이터 흐름 지도가 나온다.

## 10. 알려진 한계 (숨기지 않는다)

1. **컨센서스 EPS 시계열은 역사적 복원이 불가능하다.** H5(선행성)는 **목표주가 리비전**을
   대리변수로 쓴다. 결과는 "그 대리변수 대비 선행성"으로만 해석해야 한다.
2. **금융투자협회 전문인력 조회는 사용 불가.** 시스템 오픈이 2021-07 이라 2016~2020 구간이
   원천적으로 공백이고, (회사명+성명) 조회라 열거도 불가능하다. 인사이동 판정은
   "동일 애널이 다른 종목은 계속 커버하는가" 프록시로 대체했다.
3. **`SectorMonthFE` 를 넣는 순간 AAR_pos 는 구조적으로 섹터중립**이다. 섹터 로테이션은
   신호에서 완전히 제거된다. 설계 의도이나 명시하지 않으면 해석이 틀어진다.
4. **철회 신호는 3개월 지연**된다. 마지막 리포트가 t−3, 발화가 t(침묵을 관측한 달)다.
   t−3 을 이벤트일로 쓰면 3개월 선견이므로 이 지연은 타협 불가다.
5. **산업분류는 현재 시점 분류**를 쓴다. 변경 빈도가 낮아 영향은 제한적이나 완전한 PIT 는 아니다.
6. **한경컨센서스의 소급 범위가 신호 개시 시점을 결정한다.** 2013-08 까지 소급되지 않으면
   그만큼 백테스트 시작이 밀리며, 그 사실이 감사표에 표시된다.
7. **선행연구 고지** — 애널리스트 노력배분과 커버리지 종료의 정보성은 선행 문헌이 존재한다
   (Kelly & Ljungqvist 2012, Merton 1987 등). 이 구현의 신규성은 한국시장 횡단면 신호로의
   조작화와 철회의 인과분해에 있으며, **새로운 학술적 발견이 아니다.**
