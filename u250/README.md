## 1. ★ 캐시 최우선 (이 구현의 1원칙)

> "거의 다 수집되어 있으니 신규 수집할 필요가 거의 없다."

그래서 신규 수집은 **기본이 아니라 예외**다. `CacheLake` 가 실행 첫 단계에서 세 곳을 훑는다.

| 출처 | 무엇을 | 어떻게 |
|---|---|---|
| 구글드라이브 `_shared` | 다른 전략이 모아둔 원본·정제본 | TCD v2 와 **같은 볼트**를 쓴다. 캐시를 나누면 또 받게 된다 |
| 로컬 `D:\quant\**` | 이전 프로젝트(KR_QUANT_SUITE_V1, W012 …)가 남긴 parquet/csv/sqlite | 재귀 스캔 → 컬럼 지문으로 역할 판별 |
| 깃허브 raw | FDR 상장/폐지 목록 | 파일 목록만 먼저 확보, 필요한 날짜만 그때 수신 |

**스키마를 모르는 캐시를 어떻게 쓰는가.** 프로젝트마다 컬럼명이 다르다
(`code` / `종목코드` / `Symbol` / `ticker` …). 별칭표로 정규화하고, 역할별 지문
(필수 컬럼 + 가점 컬럼 + 파일명 힌트)에 점수를 매겨 임계 이상만 채택한다.
**애매하면 채택하지 않는다** — 잘못 채택한 캐시는 없는 캐시보다 나쁘다.

파케이는 **푸터 메타데이터만** 읽어 판별하므로 수 GB 파일도 수 ms 다.
채택한 파일은 `adopt-by-reference` 로 **경로만 등록**한다. 옮기지도 지우지도 덮어쓰지도 않는다.

```python
COLLECT_POLICY = "GAP_ONLY"   # 기본: 캐시로 못 채운 구멍만
                 "NEVER"      # 네트워크 완전 차단 (오프라인 재현)
                 "REFRESH"    # 최신 구간만 갱신
```

## 2. 사전등록을 코드가 강제한다

명세서 §8 금지사항은 약속이 아니라 **구조**여야 한다.

| 금지 사항 | 강제 장치 |
|---|---|
| 1차 결과를 본 뒤 임계·기간·N 재조정 | `SpecLock` — 실행 중 대입하면 `SpecViolation` |
| 민감도 격자를 명시 개수 이상 확대 | `SensitivityGrid` — 팩터당 5개째 등록 시 예외 |
| OOS 구간 조기 열람 | `OOSSeal` — Step 7 이전 OOS 요청은 예외, 시도 횟수까지 센다 |
| 팩터 결합 백테스트 | 결합 경로 자체를 만들지 않았다 |
| 게이트 임계값 동시 탐색 | 게이트는 `SPEC_UNIV` 에서만 읽는다. 변경 경로 없음 |

사전등록 상수 전체의 SHA256 을 매 실행 `run_log` 와 스코어카드에 남긴다.

## 3. 추측으로 채우지 않는다 (DART 엔드포인트)

명세서 §0: *"API 명칭은 참조용이다. 구현 전 실제 문서에서 검증하고, 불일치 시 로그에
기록한 뒤 진행할 것."*

엔드포인트를 코드에 박아두고 **믿지 않는다**. 실행 시각에 실제로 한 번 찔러
`status` 와 **실제 응답 필드명**을 기록한 뒤, 검증된 것만 쓴다.
검증 실패한 엔드포인트는 '없는 데이터'로 취급되어 Phase 0 커버리지에서
자동으로 걸러진다(§6.4 조기 중단). 없는 필드를 이름만 보고 채우는 경로는 만들지 않았다.

`단일판매·공급계약체결` 은 정형 API 가 확인되지 않아 **원문 파싱 경로**로 표시되며,
계약금액·매출액대비 비율이 없으면 `관측 O / 신호 X` 로 기록된다 — 그 구분이 `signal_rate` 다.

## 4. 비용 없이는 어떤 판정도 하지 않는다

총수익 경로는 **B1 하나뿐**이고 나머지 전 산출물은 비용을 통과해야 나온다.

- **증권거래세** — 연도별·시장별 실효세율 **테이블**. 하드코딩 아님
- **호가스프레드** — 종목별 **실측 우선**: Corwin-Schultz(2012) 고저가 추정량.
  추정 불가 구간만 시총분위 폴백. 음수 추정치는 0 이 아니라 **결측**으로 둔다
  (0 으로 밀면 '비용 없는 마이크로캡'이 생겨 결론이 뒤집힌다)
- **시장충격** — `coef × √(주문금액 / ADV)`. AUM 사다리 {1천만, 1억, 3억, 10억} +
  **동적 AUM**(수익률로 자본이 불어나 스스로 용량 한계에 부딪히는 경로)

## 5. 판정 게이트

`G1 무작위 대비 → G2 순수익 초과 → G3 연도 안정성 → G4 OOS → G5 다중검정 → G6 단조성 → G7 플라시보`

- **G1 이 핵심이다.** 팩터로 N종목을 뽑은 성과는 반드시 "같은 유니버스에서 무작위로
  N종목 뽑았을 때의 분포"(B4, 1,000회) 안에서 위치를 본다. 절대 CAGR 은 판정에 쓰지 않는다
- **G5** DSR 의 시행수는 팩터별이 아니라 **전체 120**(§6.2). 팩터별로 잡으면 다중검정 통제가
  무력화된다. PBO 는 CSCV
- **G7** P1(−60영업일 시프트)·P2(라벨 셔플)는 **소멸해야** 하고,
  P3(시총·업종·거래대금 매칭 대조군)는 **유지되어야** 한다

전부 통과해야 '유효'다. **전 팩터가 미달이면 그 사실을 MASTER_SCORECARD 에 명시적으로 기록한다.**
통과 팩터를 만들기 위해 명세를 수정하지 않는다.

## 7. 알려진 미해결 사항 (숨기지 않는다)

1. **리밸런싱 주기.** §1 은 "기존 구현과 동일 주기 유지"라고만 한다. 선행 문서의 NW lag 규약
   `ceil(보유세션/4.7063)` 이 주 단위 계열을 뜻하므로 `REBAL_FREQ="W-FRI"` 를 기본으로 두었다.
   월간이었다면 `"M"` 으로 바꾸면 전 산출물이 따라간다. 어느 쪽이든 `run_log` 에 남는다.
2. **게이트 원본.** `KR_QUANT_SUITE_V1.py` 가 실행 환경에 있으면 4380–4394행을 파싱해
   상수를 대조한다. 없으면 §1 표의 상수로 재현하고 그 사실을 로그에 남긴다.
3. **자본잠식 정의.** `자본총계 ≤ 0`(완전) 또는 `자본총계 < 자본금`(부분)으로 구현했다.
   완전잠식만 적용했을 때의 차이 건수를 진단으로 출력한다(대안 백테스트는 만들지 않는다).
4. **G5 의 'DSR > 0'** 은 DSR 을 확률로 정의하면 항상 참이라 사실상 비구속이다.
   명세대로 판정하되 실질 판정에 해당하는 `SR > SR₀` 를 비고에 함께 남기고,
   **명세 개정 요청**으로 스코어카드에 기록한다. 코드에서 임계를 바꾸지 않았다.
