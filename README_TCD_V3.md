# TCD v3 · 전략 3 — CORE-D + EMP-LITE

DART 직원현황(`empSttus`) 기반 **한계임금** 전환 코어. 명세서 v3 구현체.

> **이 전략이 재는 것**
> ```
> 한계임금     = Δ(연간급여총액) / Δ(직원수)
> 임금프리미엄 = 한계임금 / 전기 1인평균급여액
>
>   wage_premium < 1  →  저임금 대량채용. 정책보조금 유인 채용 의심
>   wage_premium > 1  →  기존보다 비싼 사람을 뽑음. 진짜 역량 확충
> ```
> 정책 오염 필터가 별도 패치가 아니라 **산식 자체에 내장**되어 있다는 것이 핵심 가치다.

## 2. 구글드라이브 캐시 — 절대 1원칙

**기존 캐시·인덱스를 훼손하지 않는다.** 약속이 아니라 **구조**로 보장한다:

1. 인덱스의 진실은 **append-only JSONL 저널**. 기존 줄을 다시 쓰지 않으므로 과거 기록이 사라질 수 없다.
2. `index.parquet` 은 저널의 파생물. 재생성 전 **항상 타임스탬프 백업**, 실패 시 컴팩션 자체를 건너뛴다.
3. 컬럼은 **합집합으로만 확장**. 다른 전략이 쓰던 컬럼을 떨어뜨리지 않는다.
4. blob 은 **내용해시 경로**. 같은 내용은 재기록조차 하지 않는다.
5. 이미 드라이브에 있던 리포트는 **이동·개명 없이 경로만 등록**(adopt-by-reference).
6. **삭제 API 자체가 없다.** 손상 파일조차 지우지 않고 `.corrupt` 로 격리만 한다.

```
{GDRIVE_ROOT}/
├── _shared/                    ← 공용 인덱스: 다른 전략이 그대로 재사용
│   └── table/{krx_ohlcv_daily, dart_fnltt_raw, dart_multi_raw, dart_disclosures,
│              dart_employees_ext★, emp_sensors_annual★, krx_investor_flows,
│              krx_listing_snapshots, research_report_master, analyst_master,
│              report_analyst_link}
└── tcd_v3_core_d_emp/          ← 전용 인덱스: 이 전략 고유
    ├── table/{l1_features_*, l2_scores_*, backtest_returns_*}
    └── reports/TCD_V3_CORE_D_EMP_LITE/{canary_report, emp_coverage, panel.parquet,
                                        backtest_full.json, r2n_verdict, r10_policy_calendar,
                                        runtime.csv, returns/holdings/log}
```

★ = v3 가 새로 만드는 공용 자산. `dart_employees_ext` 는 코어 v2 의 `dart_employees` 가 버리는
`jan_salary_am`(1인 평균급여)·`rgllbr_co`(정규직수)까지 담으므로, **다른 전략도 한계임금을
바로 계산할 수 있다.** 테이블명을 분리했기 때문에 기존 `dart_employees` 를 덮어쓰지 않는다.

> ⚠ 이번 작업에서 **공용 가격 캐시 파괴 버그를 고쳤다.** `fetch_prices` 가 백테스트 창으로
> 잘라낸 프레임을 공용 테이블에 그대로 덮어써서, 창 밖의 과거가 활성 parquet 에서 영구히
> 사라지고 있었다(백업은 남지만 `get_table` 은 활성 파일만 읽는다). 이제 저장은
> **기존 캐시 ∪ 신규**로 하고 반환만 창으로 자른다.

## 3. 스펙 §0 의 7대 원칙 — 코드로 강제

| # | 원칙 | 강제 방법 |
|---|---|---|
| 1 | PIT 조인은 `merge_asof` 단일 패스 | `PIT.asof_join` 만 사용. 빌드 시 `direction='backward'` 존재 검사 + 결합 직후 `kd_* > month` 전수 검사 |
| 2 | TP 는 `clip(z,0) × clip(z,0)` | 빌드 시 소스 패턴 검사 + 계약검정이 **최악 사분면의 TP 가 0인지** 실측 |
| 3 | 셀 정규화는 `rank(pct=True)`+`transform` | 빌드 시 `groupby(...).apply(` 존재하면 빌드 실패 |
| 4 | 유니버스·매핑 전부 PIT | `Universe.at` + 계약검정 C2/C13 (미래 상장 종목 배제 실측) |
| 5 | 벤치마크 하드코딩 금지 | R0 가 매 실행 유니버스 동일가중을 **직접 측정**. 소스에 성과 리터럴이 있으면 계약검정 실패 |
| 6 | 한계임금 분모 불안정 → 결측 | C15 (a)(b)(d) 게이트 + `test_c15` 자가검정. 0 채움·ffill 경로가 없다 |
| 7 | 상장폐지 포함, 정리매매 없으면 -100% | 백테스트 엔진이 강제 + 빌드 시 존재 검사 |

## 4. 이 전략의 설계 결정 (v2 와 다른 점)

- **EMP 센서는 연도 프레임에서 계산한다.** 월 패널에 먼저 붙인 뒤 `diff(12)` 를 하면
  제출일(`rcept_dt`)이 해마다 밀리는 구조 때문에 "12개월 전 행"이 같은 사업연도를 가리키는 달이
  생겨 Δ직원수=0 이 되고, C15(a) 가 그 관측을 조용히 버린다. 연도 프레임에서 계산하면 Δ는 언제나
  정확히 1개 사업연도 간격이고, PIT 안전성은 `merge_asof(knowledge_date=rcept_dt)` 가 보장한다.
- **TP 는 랭크 기반 clip 곱.** 결과가 항상 `[0, 0.25]` 라 "최악이 최고점"이 **구조적으로 불가능**하다.
  v2 는 `z×z` 를 쓰고 팩마다 `where(z>0)` 로 손보는 방식이었다.
- **셀 = `month × ind_mid × size_bucket(3단계)`.** 버킷 경계는 중소기업기본법 상시근로자수
  (300 / 1,000명)를 그대로 따른다 — 정책 요건이 규모에 연동되므로 셀 내 공통충격으로 흡수된다.
- **경량화.** v2 의 축 기반 스코어링(팩 레지스트리·E_AXB/E_AXC·R4/R6/R9/R11)은 v3 스펙과 다르므로
  **포함하지 않았다.** 죽은 코드를 남기지 않는다. 수집·캐시·HTTP·PIT·백테스트 엔진은 이미 실전에서
  다듬어진 v2 조각을 그대로 재사용한다.

## 4.5 적대적 감사에서 확정된 결함 (전부 수정됨)

6개 렌즈로 찾고 회의론자가 반증을 시도해 **7건 확정 / 3건 기각**. 기각된 3건은 고치지 않았다.

| 결함 | 왜 조용한가 |
|---|---|
| **`axis_U_v3` 의 수급 월 배치가 라벨 정렬** | `f["month"] = as_ts_series(<ndarray>)` 는 값은 위치로 계산하고 배치는 **라벨**로 한다. 바로 위 `sort_values` 가 순서를 바꾼 순간 2026년 A종목 행이 2016년 B종목의 달을 받는다 → `groupby(code,month).last()` 가 **미래 수급을 과거 달로** 실어 보낸다. d3→U→Signal 로 전 종목 랭킹이 오염된다. d3 는 `PIT.asof_join` 을 타지 않아 C1 이 못 잡는다 → 회귀 테스트 **C1b** 신설 (버그판에서 FAIL 확인) |
| **거래정지→폐지 경로가 0% 청산** | 정지되면 그 달부터 패널에 행이 없어지는데 실제 폐지일은 3~24개월 뒤다. '다음 달 안'만 보면 이 경로가 통째로 빠져나간다 → '다시 안 나타나는가' + 24개월 지평으로 판정 |
| **서킷브레이커가 정상 응답에 터짐** | DART `status 013`(그 해 미제출)은 **정상 응답**인데 실패로 세고 있었다. 신규상장·폐지사는 초기/말기 연도가 통째로 013 이라 12스레드 공유 카운터가 쉽게 15에 도달 → 남은 수천 건을 포기하고 '차단당한 듯'한 오해를 남긴다 |
| **`size_positions` 가 절반을 0 비중으로** | `clip(s - median, 0)` 이라 선정 종목의 **정확히 절반**이 `1e-9` 로 깔린다. 25종목 선정 → 실효 12종목(실측). '평균종목수'와 분산효과가 2배 넘게 부풀려진다 → 순위 기반으로 교체(실측 25/25) |
| **지수 벤치마크가 한 달 어긋남** | 전략은 `fwd_ret`(월 m 행 = m+1 실현) 규약인데 지수는 `pct_change()` 그대로였다. 시장요인이 상쇄되기는커녕 두 배로 들어가 초과수익 t값이 절반으로 눌린다 |
| **`nl_vapp` 가 공시 완비도를 잼** | 부가가치 3항목을 각각 `fillna(0)` 하므로, 인건비가 작년 결측→올해 기재면 실제 개선이 없어도 급등한다. TP_N2 는 그걸 '희석 없는 확장'으로 읽는다 → t 와 t-12 의 **관측 구성이 같을 때만** 차분 |
| **V3 거부권 창이 '행 3개'** | U-MID 로 잘린 패널은 종목별 행이 월 연속이 아니다. `rolling(3)` 은 (a) 창이 실제 6~9개월로 늘어나고 (b) 공시 달에 행이 없으면 이벤트가 아예 사라진다 → 이벤트 날짜에서 직접 달력 3개월을 펼침 |

## 4.6 2차 실행에서 드러난 결함 (전부 수정됨)

실사용 로그 한 편이 **자원 상태를 데이터 사실로 오독하는** 결함군 전체를 드러냈다.
직접 원인은 하나였지만, 같은 뿌리에서 나온 조용한 손상이 두 건 더 있었다.

### 뿌리 — `dart_api()` 가 서로 다른 다섯 사건을 전부 `None` 으로 뭉갰다

```
예산 게이트 거부 / 네트워크 실패 / 인증 오류 / 한도초과 응답 / 013(데이터 없음)
                          ↓  전부 None
                    호출자는 구별할 수 없다
```

DART 일일 한도가 **이미 소진된 상태로 시작한** 실행에서 모든 호출이 예산 게이트에 막혔고,
CANARY 는 그것을 '데이터 없음'으로 읽어 K8 을 FAIL 시키고 §12-2 킬 기준으로 실행을 죽였다.
데이터는 멀쩡했다. 더 나쁜 건 처방이었다 — **"백테스트 시작연도를 상향하라."**
오늘 호출권이 없다는 일시적 사실로 10년 구간을 영구히 잘라낼 뻔했다.

수정: `dart_halt_reason()` 을 도입해 사유를 1급 값으로 만들고, 그 상태의 DART 검사는
FAIL 이 아니라 **판정 보류(SKIP)** 로 기록한다. 킬 기준은 걸리지 않는다.
DART 와 무관한 K5(생존자편향)는 **완화되지 않는다** — 계약 §12-R 이 양쪽을 다 강제한다.

### 조용한 손상 ① — 공시목록의 절반 페이지가 '완결'로 캐시됐다

`have_months` 를 캐시 행의 존재로 유도했다. 12페이지짜리 달을 3페이지에서 놓쳐도
1~2페이지가 저장되는 순간 그 달은 영원히 '보유'가 되고 나머지는 두 번 다시 시도되지 않았다.
잃는 것이 유상증자·전환사채·자기주식 공시라, 하류(V3 희석 거부권·PACK-C)는 **'이벤트 없음'**
이라는 정상적인 값을 읽는다 — 경고도 FAIL 도 없이, 재실행할수록 그 거짓이 굳는다.

수정: 완결성 원장(`dart_disclosure_months`)을 분리하고 **페이지를 끝까지 훑은 달만** 기록한다.
기존 캐시는 (달×유형)당 1회짜리 탐침으로 `total_count` 와 대조해 **이미 뚫린 구멍을 찾아 복구**한다.

### 조용한 손상 ② — 예산이 모자란 실행이 스스로 백테스트 창을 잘랐다

수집 잡은 연도 내림차순이라 `jobs[:cap]` 은 **항상 오래된 연도부터** 버린다. 그러면 §6 커버리지
표가 '최근은 두껍고 과거는 얇은' 모양이 되는데, 그건 DART 의 사실이 아니라 **우리 지갑의 사실**이다.
`COVERAGE_AUTO_TRIM=True` 가 그 모양을 읽고 창을 잘랐고, 단축은 §6 데이터 근거로 리포트에 박혔다.

수정: 절단이 발생하면 `EMP_TRUNCATED` 에 기록하고, 그 실행에서는 자동 창 단축을 **걸지 않는다.**

### 같은 뿌리의 나머지

| 결함 | 수정 |
|---|---|
| 서킷브레이커가 예산 거부를 '실패'로 세어 15건 만에 터짐 (매 호출 0.05~0.15초 낭비) | 예산이 막혔으면 **한 건도 시도하지 않는다.** 중단 사유를 추측 대신 실제 값으로 보고 |
| `"백테스트 시작일을 None년 이후로 상향"` | 탐침이 아무것도 못 받았으면 시작연도 권고를 **아예 하지 않는다** |
| 중단 경로가 `DBUDGET.close()` · `report_http()` 를 건너뜀 | 중단은 진단이 가장 필요한 순간이다 — 원장과 HTTP 감사표를 반드시 남긴다 |
| 0.35초에 '잔여 0'을 알고도 16분 30초를 쓴 뒤 죽음 | **사전 게이트**(`preflight_dart_v3`) — 캐시가 있으면 캐시 전용으로 진행, 없으면 지금 멈추고 선택지 4개를 제시 |

### 별개로 발견된 것 — 폐지의 절반을 전액손실로 계상하고 있었다

폐지목록 원본의 `Reason` 을 실측했다. 2016년 이후 폐지된 주권 561건 중

```
피흡수합병 60 · 스팩소멸합병 53 · 완전자회사화 43      → 인수기업 주식을 받는다
스팩 예심 미제출 · 해산 · 존속기간 만료  ~130          → 예치금이 공모가+이자로 반환된다
────────────────────────────────────────────────────────────────
308건 (55%) 이 전액손실이 아닌데 -100% 로 계상되고 있었다
```

U-MID 대역의 연 폐지율(~4.9%)과 25종목 포트폴리오로 환산하면 **연 -2%p 안팎의 없는 손실**이다.
이건 보수적인 게 아니라 그냥 틀린 것이다. 반대 방향의 함정도 있어서, 프리미엄을 지어내지 않고
**직전 관측가 청산**으로만 처리한다(실제 합병 프리미엄보다 낮으므로 여전히 보수적).
사유를 모르는 건(`unknown` 81건)은 **-100% 를 유지**한다 — 그쪽이 진짜 보수다.
계약 **C2c** 가 양방향을 강제한다: 합병을 전액손실로 계상해도 실패하고, `unknown` 을
관대하게 처리해도 실패한다.

### 성능 — 병목은 네트워크가 아니라 우리가 건 자물쇠였다

```
1,833건 × 0.5초(krx 버킷 2.0 qps) = 916.5초   ←  관측 916.7초
```

`_px_fdr` 는 이름과 달리 내부적으로 **네이버**(fchart)를 때리는데 `krx` 버킷(2.0 qps)의 토큰을
먹고 있었다. `RateLimiter` 는 소스당 전역 단일 간격이라 12스레드의 실효 동시성이 **1** 로 떨어진다.
수집 시간의 100%가 대기였다.

더 큰 것은 그 1,834종목의 정체였다. '앞 구간 결손' 판정 기준이 요청 시작일(2015-02)이라
**2021년 상장 종목은 조건이 영원히 참**이다 — 매 실행 전 구간을 다시 받고 있었다(캐시 3,517종목의 42%).

수정: ① 버킷을 `naver` 로 정정 ② 상장일 + '최초 관측일 워터마크'로 하한을 올려 재수집을 차단.
거래대금 근사 경고도 `fdr` 경로를 포함하도록 고쳤다(1,487종목에 대해 안 뜨고 있었다).

## 5. R2-N — 이 문서의 존재 이유

```
A. clip(z(nl_emp),0) 단독      ← 나이브        C. TP_N1 = clip×clip   ← 트레이드오프
B. clip(z(nl_premium),0) 단독                  D. 전체 E (8 TP) vs CORE-D 단독 (5 TP)
```

- `C > max(A,B)` 유의(HAC t>1.65) → **PASS.** 국민연금 월 해상도로 정밀화할 가치가 있다는 근거 확보.
- `C ≈ max(A,B)` → 트레이드오프 논리 무기여. 연 1회 해상도의 한계.
- `D ≤ CORE-D` → EMP 신호 전체가 무기여 → CORE-D 축소안을 병행 제시.

**A·B·C 는 두 센서가 모두 관측된 동일 행 집합에서 비교한다.** 이 통제를 빠뜨리면 나이브 팔이
표본 수 덕분에 이긴다. 판정은 `r2n_verdict.md` 로 저장되며 **유리하게 해석하지 않는다.**

### 강건성 판정에서 지킨 것

기준선에 애초에 알파가 없으면 R3·R7·R10 은 **PASS 가 아니라 판정 유보(N/A)** 를 낸다.
이걸 막지 않으면 기준 Sharpe 가 -0.05 인데 직교화 후 0.04 가 나왔다는 이유로 "알파 잔존"이
찍히고, 아무 알파도 없는 전략이 강건성 검사를 3개나 통과한 것처럼 보인다. 스펙 §11 이 금지하는
'유리한 해석'의 가장 전형적인 형태다.

R1(누수 자가검정)의 판정 근거는 **미래수익 직접주입 대조군 하나**다. 신호 앞당김 대조군은 참고로만
쓴다 — 앞당겨서 개선되려면 신호에 실제 예측력이 있어야 하므로, 그 미개선은 하네스 결함이 아니라
'신호에 지속성이 없다'는 **별개의 사실**이기 때문이다. 둘을 한 판정에 묶으면 두 사건을 구별할 수 없다.

## 6. 알려진 한계 (숨기지 않는다)

1. **U-MID 의 규모 랭크는 시가총액이 아니라 20일 평균거래대금 랭크다.** 파이프라인이 확보하는
   소스에 과거 시점 시가총액이 일관되게 없고, 현재 주식수를 과거에 적용하면 그 자체가 미래누수다.
   한국 시장에서 두 순위의 상관은 높지만 동일하지 않다.
2. **컨센서스 fwd EPS 시계열은 과거 복원이 불가능하다.** U축 `d1` 의 E 는 후행 12M 순이익 대리를
   쓴다. 초기 구간일수록 오차가 크다.
3. **`empSttus` 는 별도 기준에 가깝다.** 1인당 부가가치의 분자도 별도(OFS) 우선으로 맞췄으나,
   연결 비중이 큰 지주회사에서는 오차가 크다.
4. **밸류업 프로그램은 2024년 이후다.** TP_P1/P2 는 10년 중 최근 2년만 현 레짐이다. 2024년 이전
   알파가 0이면 정책 베팅이지 구조적 알파가 아니다 — R7 이 판정한다.
5. **DART 전체 커버리지는 일일 호출한도(20,000) 때문에 2~3회 실행에 나눠 완성된다.**
   단 **한 번의 실행은 항상 4시간 안에 끝나고**, 첫 실행에서도 백테스트·강건성 전 출력물이 나온다.
   상한(`EMP_MAX_CALLS` / `DART_FS_MAX_CALLS`)은 계약 §12-6 이 강제하며, 상한을 지우면 실행이
   시작조차 되지 않는다. 자세한 예산 구조는 §8.
6. **이 전략은 우측 꼬리 의존적이다.** 상위 5% 종목 제외 시 성과가 사라지는지 매 실행 측정해 출력한다.
7. **한경컨센서스·네이버금융은 `robots.txt` 가 `Disallow: /`.** 사용자의 명시적 지시에 따라 수집하되
   보수적 속도로 제한하고 그 사실을 로그에 명시한다. PDF 원문은 증권사 저작물이므로 로컬 분석 용도로만.

## 8. 수집 호출 예산 — 4시간 계약을 지키는 구조

DART 재무·직원현황은 잡 수가 **곱셈으로 폭발**한다. 상한이 없으면 이렇게 된다:

```
fnlttSinglAcntAll : 3,981사 × 13년 × 4분기 = 207,012 호출 = 일일한도 기준 11일
empSttus          : 3,981사 × 13년         =  51,753 호출 =              3일
```

실제로 한 번 터졌다. v2 코어의 `fetch_dart_financials()` 는 주석에 "콜드빌드는 4시간 예산
밖"이라 적힌 **다일(多日) 빌드 전용** 함수인데, ≤4시간이 하드 계약(§12-6)인 v3 가 상한 없이
그대로 물려 썼다. tqdm 이 `173/207012 [00:31<11:29:19]` 를 띄웠을 때는 이미 돌고 있었다.

### 지금의 구조

| 층 | 엔드포인트 | 비용 | 이번 실행 상한 |
|---|---|---|---|
| Tier-1 | `fnlttMultiAcnt` | **100사/호출** — 전 종목 10년이 ≈2,100회(5분) | 없음(항상 전량) |
| ① EMP | `empSttus` | 1사×1년 | `EMP_MAX_CALLS = 14,000` (≈30분) |
| ② Tier-2 | `fnlttSinglAcntAll` | 1사×1기간 | `DART_FS_MAX_CALLS = 12,000` (≈40분) |

세 가지가 폭발을 막는다.

1. **모집단 축소** — `DART_FS_UNIVERSE_ONLY` / `EMP_UNIVERSE_ONLY`. 전 기간 한 번도 U-MID
   대역(투자가능)에 들지 못한 종목은 어떤 달에도 편입될 수 없고 셀 정규화도 U-MID 패널
   안에서만 이뤄지므로, 그 종목의 전체재무제표·직원현황은 **스코어에 한 줄도 쓰이지 않는다.**
   U-MID 판정은 가격패널(20일 평균거래대금 랭크)만으로 내리므로 재무를 미리 들여다보지 않는다.
2. **연간 우선** — `DART_FS_FREQ = "annual"` 이면 호출이 정확히 1/4. 한계임금 축이 연간이라
   첫 실행에서 짝이 맞는 쪽이 먼저 완성된다.
3. **우선순위 절단** — 상한에 걸리면 *'U-MID 대역에 머문 달 수'가 많은 종목 × 최근 연도*
   순서로 자른다. 유동성 1등이 아니라 **실제로 담길 확률이 높은 종목**부터다.

예산은 알파 순서로 배분한다. 한계임금이 이 전략의 알파 원천이므로 **L1.EMP 가 L1.DART 보다
먼저** 돌고 일일 예산을 먼저 가져간다. Tier-2 는 남는 예산으로 채우고, 못 받은 (회사×기간)은
`merge_financial_tiers()` 가 Tier-1 주요계정으로 메운다 — 그래서 첫 실행에서도 유니버스·규모버킷·
R3 팩터는 전부 동작한다. 재고·매출채권·영업CF 가 필요한 TP_I1/TP_I2 만 커버리지가 낮게 시작하고
재실행할 때마다 올라간다.

수집 전에 **예산표를 먼저 출력**한다(`announce_budget_v3`). 4시간 계약은 사후 판정이 아니라
사전 상한이어야 하기 때문이다. 상한을 `None` 으로 바꾸면 계약 §12-6 이 FAIL 하고 실행이
시작되지 않는다(버그판에서 FAIL / 정상판에서 PASS 양방향 확인).
