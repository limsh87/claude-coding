# ARC-BDF — 리포트 × 자사 거래원 플로우 (SPEC-B)

한국 상장사 「리서치 배포강도」 탐지 퀀트 시스템. 백테스트 구간 **2016-08 ~ 2026-07 (10년)**.

> **리서치의 가치는 발간 자체가 아니라 세일즈 채널을 통한 배포 강도에 있다.**
> 한국은 종목별 거래원(회원사) 매매동향이 상위 5개 창구 기준으로 일별 공개되는 드문 시장이고,
> 이 데이터는 배포 강도의 관측 가능한 그림자다.
> **확증**: A증권 매수리포트 + A증권 창구 순매수 → 롱
> **페이드**: 리포트 직후 자사 창구 순매도 → 물량 분배 신호 → 배제

## 2. ★ KRX 없이 PIT 유니버스를 세우는 법

KRX 로그인이 차단된 상태를 전제로 설계했다 (`KRX_ENABLE = False` 가 기본값).
KRX 자격증명 입력란은 상단에 그대로 있고, `True` 로 바꾸면 **교차검증용 보강**으로만 쓴다.

| 필요한 것 | KRX 대체 경로 |
|---|---|
| 일별 시세 | FinanceDataReader → 네이버 siseJson → 네이버 HTML → yfinance (4중 폴백) |
| **PIT 시가총액 · 상장주식수** | **공공데이터포털 금융위 주식시세정보** (`basDt` 하루로 전종목, 10년=2,450요청) |
| **일별 상장 스냅샷** | 위 API 의 그날 관측 종목 = 추정이 아니라 **관측** |
| 상장폐지 이력 | FDR `listing/delisting` GitHub 캐시 (KRX 인증 무관) |
| 상장일 | KIND 상장법인목록 + FDR 상장목록 |
| 투자자 수급 | 네이버 `frgn.naver` (페이지 소급) |
| 외국인 순매수 | 네이버 siseJson **외국인소진율 차분** — 종목당 1요청으로 10년치 |

시가총액은 **5단 사다리**로 만들고 `(code, date)` 마다 어느 단을 썼는지 기록해 감사표로 출력한다.
조용히 틀린 시총을 쓰는 것이 최악이기 때문이다.

```
T0  공공데이터 시총(관측)          ← 미래정보 없음. 가장 정확
T1  DART 주식총수 × 종가            ← PIT. DART 키 필요
T2  현재 주식수 × 종가              ← 주식수 변동이 과거로 투영됨
T3  현재 시총 × 종가비              ← T2 의 축약
T4  20일 평균 거래대금 백분위       ← 랭크 전용 대용치
```

이 전략에서 시총은 **전부 랭크/버킷으로만** 쓰인다(§6.5 통제, H4, 슬리피지 구간, 하위1000 비교).
레벨로 쓰지 않으므로 강등돼도 결론이 뒤집히지 않지만, T0/T1 비중은 반드시 보고한다.

## 3. ⚠ Phase 0 — 이 전략이 죽을 확률이 가장 높은 지점

**병목은 알파가 아니라 「거래원별 일별 매매동향의 과거 이력」 확보다.**
그래서 코드를 더 쓰기 전에 코드가 스스로 소스를 찔러보고 판정한다.

네이버 거래원 탭은 **최종 거래일 1일치 스냅샷 전용**이다. 날짜 파라미터도 페이지네이션도 없다
(같은 종목 페이지의 일별시세·외국인기관 탭에는 `&page=` 가 있는데 거래원 탭에만 없다 —
설계상 이력이 없다는 강한 신호다). 공공데이터포털에 해당 데이터셋이 없고, 증권사 OpenAPI 는
'현재가 기준' 스냅샷이거나 Windows COM 종속이라 소급이 불가하다.

| 판정 | 분기 |
|---|---|
| 10년 확보 | ARC-BDF 원 가설 그대로 |
| 3~10년 | 확보 구간으로 축소 + 검정력 영향 명시 |
| **3년 미만** | **B-1 전진수집 스크립트 생성 + B-2 ARC-BDF-PROXY 백테스트** |

**PROXY 로 떨어지면 그것은 원 가설의 대리 검증이 아니다.**
단순히 기관+외국인을 합치지 않고 **발행사 계열 정합**(외국계 하우스 → 외국인 / 국내 하우스 → 기관)
으로 브로커 정체성을 부분 보존하되:

- **H3(중소형 증권사 강세) → 원리상 검정 불가** (창구 단위가 사라졌으므로)
- H5(리포트 조건부 우위) → 주체 단위로만, 약화된 형태로 검증
- H1 / H2 / H4 및 look-ahead·생존편향 방어는 그대로 유효
- **"ARC-BDF 10년 백테스트 완료" 라고 보고하지 않는다**

동시에 B-1 전진수집이 매 실행마다 오늘자 거래원 스냅샷을 공용 인덱스에 적재한다.
3년이 쌓이면 같은 코드가 자동으로 PARTIAL 분기로 올라선다.

## 4. 구글드라이브 캐시 — 절대 1원칙

**기존 캐시·인덱스를 훼손하지 않는다.** 약속이 아니라 **구조**로 보장한다:

1. 인덱스의 진실은 **append-only JSONL 저널**이다. 기존 줄을 다시 쓰지 않는다.
2. `index.parquet` 은 저널의 파생물이며 재생성 전 **항상 타임스탬프 백업**.
3. 컬럼은 **합집합으로만** 확장. 스키마가 달라도 기존 컬럼을 떨어뜨리지 않는다.
4. blob 은 **내용해시 경로**에 쓰므로 덮어쓰기 자체가 발생하지 않는다.
5. 이미 드라이브에 있던 리포트는 **이동·개명 없이 경로만 등록**한다 (adopt-by-reference).
6. **삭제 API 자체가 없다.** 손상 파일조차 `.corrupt` 로 격리만 한다.

```
{GDRIVE_ROOT}/
├── _shared/     ← 공용 인덱스: 다른 전략도 그대로 재사용
│   └── table/{price_daily, dgk_stock_price_daily, research_report_master,
│              analyst_master, report_analyst_link, broker_member_map,
│              naver_investor_flow, naver_foreign_ratio,
│              naver_member_flow_snapshot, dart_stock_totqy, ...}
└── arc_bdf/     ← 전용 인덱스: 이 전략 고유 (이벤트패널·백테스트 결과·리포트)
```

`GDRIVE_ROOT` 를 TCD v2 와 같은 값으로 두면 **공용 인덱스가 그대로 재활용**된다.

## 5. look-ahead 방어 (위반 시 산출물 전체 무효)

거래원/수급 데이터는 **장 마감 후 공개**된다. 진입은 최소 `d+1` 종가다.

```
k=0   윈도 → 진입 d+1 종가
k=0..2 윈도 → 진입 d+3 종가
```

코드에서 이 오프셋은 `entry_offset = k+1` 로 강제되고, 계약 **K1** 이 실행 시 재확인한다.

**베이스라인의 숨은 미래참조** — `FLOW_raw(d′)` 는 `d′..d′+K` 를 쓴다. 따라서 `d′=d−1, K=2` 면
그 값은 `d+1` 을 포함한다. '과거 60일 중앙값'이라 쓰고 그냥 `shift(1)` 하면 미래가 새어 들어온다.
→ 베이스라인은 반드시 `(K+1)` 만큼 밀어서 계산한다 (계약 **K2** 가 실증 검사).

그 외 PIT 강제 지점: 상·하위 30% 컷(K6), 통제회귀 계수(과거 1년 이벤트로만 적합),
시총 랭크(그날 횡단면), 하위1000 선정(매 거래일 재선정).

## 6. 계약 자동검정 K1~K16

실데이터를 만지기 전에 **협상 불가 규칙**을 코드가 스스로 검사한다. 하나라도 실패하면 중단한다.

| ID | 계약 |
|---|---|
| K1 | 진입 시점 `d+k+1` 강제 |
| K2 | 이중디민 베이스라인 미래참조 차단 (미래 값을 바꿔도 과거 잔차 불변) |
| K3 | PIT 유니버스 상장전/폐지후 배제 |
| K4 | **상위5 절단 → 순매수 결측 보존** |
| K5 | 연도별 증권거래세 (단일세율 금지) |
| K6 | PIT 분위 컷 미래정보 차단 |
| K7 | 증권사 매핑 오매칭·사명재사용 |
| K8~K13 | BH-FDR / DSR / PBO / 블록부트스트랩 / 정규분포 / Newey-West |
| K14 | **tz-aware 날짜 하루밀림 방지** |
| K15 | 빈 프레임 dtype 오염 방지 |
| K16 | 목표가 결측·"0" 처리 |

### K4 가 왜 협상 불가인가

거래원은 **상위 5개만** 공개된다. 매수 top5 에만 나온 창구의 '매도량'은 0이 아니라 **미상**이다.
이를 0으로 채우면 순매수가 체계적으로 과대추정되고, **대형 창구일수록 편향이 커져
알파처럼 보이는 가짜 신호가 만들어진다.** 반드시 `NaN` + 상한(그날 5위 창구 거래량)으로 둔다.

## 8. 통계 검증 (SPEC §9)

| 항목 | 구현 |
|---|---|
| 블록 부트스트랩 | 순환 블록 21영업일 × 1,000회 (자기상관 보존) |
| PBO | CSCV, `C(8,4)=70` 조합, logit ≤ 0 확률 |
| DSR | `E[max SR]` 반영, 시도 12회 명시 |
| 워크포워드 | 학습 5년 / 검증 1년 롤링 (표본이 짧으면 창을 줄이고 그 사실을 로그) |
| BH-FDR | q=0.10 (+ BY 보수 기준 병기) |
| Newey-West | Bartlett, `L=floor(4(T/100)^(2/9))` — statsmodels 없이도 동작 |
| **플라시보** | 이벤트 날짜 ±20~60영업일 이동. **유의하면 KILL** |

**겹치는 보유구간의 t 과대추정**은 캘린더타임 포트폴리오 구조로 흡수한다 —
이벤트별 수익률의 횡단면 상관이 포트폴리오 수익률 하나로 합쳐지기 때문이다.

## 9. 비교 전략 — 시총 하위 1000

동일한 파이프라인·동일한 사전등록 격자를 **유니버스만 바꿔** 재실행하고 비교표를 낸다.
H4('저유동성·소형주에서 더 강하다')의 직접 검정이기도 하다.

하위 1000 은 **매 거래일 횡단면에서 재선정**한다. 오늘의 시총으로 과거를 자르면 그 자체가
미래참조이며, 그 경우 소형주 성과가 크게 과대평가된다.

소형주는 편도 슬리피지가 **35bp** 로 대형주(10bp)의 3.5배다. 총수익이 높아도
비용 반영 후 초과가 남는지는 비용 민감도표에서 따로 확인해야 한다.

## 10-b. 수집 예산과 '반복 수집 금지' 장치

이전 판이 FULL 모드에서 30분 넘게 멈춘 원인은 알고리즘이 아니라 수집 계층이었다.
아래 다섯 개 장치가 그 원인을 각각 하나씩 제거한다.

| 장치 | 무엇을 막는가 | 손잡이 |
|---|---|---|
| 네트워크 사전 점검 | 막힌 네트워크에서 수천 건 × 4회 재시도 = 수 시간 무반응 | (자동) |
| 공공데이터 벌크 승격 | 종목별 요청 수천 건. DGK 패널이 곧 OHLCV 다 | `DGK_ROWS_PER_REQ` |
| 실패 종목 원장 | 존재하지 않는 코드를 매 실행 다시 긁는 것 | `PRICE_DEAD_COOLDOWN_DAYS` |
| 소스 서킷 브레이커 | 죽은 소스(yfinance 레이트리밋 등)를 계속 때리는 것 | (자동, 예외 1점·빈응답 0.2점) |
| 시간 예산 + 증분 저장 | 중단 시 전량 소실 | `PRICE_BUDGET_MIN`, `PRICE_FLUSH_EVERY` |

**호출량 설계.** 10년 = 약 2,450 거래일. `numOfRows` 를 한 번에 다 받으므로 공공데이터는
**하루 1요청 = 총 약 2,450회**다(1,000행씩 쪼개면 3배가 된다). 일일 한도는 코드에 박아두지
않는다 — 포털이 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` 를 응답하는 순간의
사용량을 '관측된 실제 한도'로 기록하고, 다음 실행은 그 실측값을 알고 시작한다.

**상태 파일은 드라이브 전용 인덱스 아래 `state/` 에 둔다.** `outputs/` 에 두면 Colab 세션이
끝날 때 사라지고, '이미 실패한 종목을 다시 긁지 않는다'는 약속이 매번 깨진다.

**모드 전환은 코드 수정 없이:** `ARC_BDF_RUN_MODE=SMOKE|FULL|CACHED|PHASE0` 환경변수.
